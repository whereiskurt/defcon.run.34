# CTF Share-Link Unfurl — Vegas Cherries (design)

**Date:** 2026-07-18
**Branch:** `feat/ctf-share-unfurl-cherries`
**Status:** approved — implementing to PR

## Problem

When a CTF flag-award share link `https://q.defcon.run/c?v=<CODE>` is pasted into
Slack / Discord / iMessage / Twitter, it produces **no preview card** — the
`q.defcon.run` resolver Lambda returns a bare `302`, so social crawlers get
nothing to render. We want a fun, on-brand **Vegas "3 red cherries" slot-machine**
unfurl with a neon / electro-fluorescent vibe. Not every QR needs it — it should
be an **opt-in** per-code option, aimed at flag awards.

## Decisions (locked with the user)

1. **Code stays secret.** The public preview card never prints `v=<CODE>`.
2. **Humans get an instant redirect** — unchanged `302` behavior. No splash delay.
3. **Reusable opt-in**, not a one-off: a per-`Qr` `unfurl` theme flag; `c` is the
   first code to use it.
4. **Resolver-served image** — the `og:image` PNG ships in the Lambda bundle.

## Approach

Because humans redirect instantly and the code must stay secret, the resolver
**UA-sniffs**: link crawlers get an HTML card; every other client gets the
existing bare `302`. Missing a crawler UA just yields no card (graceful); a human
never touches the HTML, so the code can never leak through a preview fetch.

```
q.defcon.run/c?v=<CODE>
  → CF E4SID56HIMXZW (CachingDisabled) → ALB → resolver Lambda
  → parsePath: code="C", query="v=<CODE>"
  → getQr("C"): item.unfurl == "cherries"?
       ├─ crawler UA?  YES → 200 text/html: og:*/twitter:card meta,
       │                     og:image = https://q.defcon.run/_og/cherries.png,
       │                     neon body, meta-refresh + JS replace → destination
       │                     BASE (v STRIPPED, region-prefixed) — secret-safe
       │               NO  → existing 302 → enriched destination (with v)  [unchanged]
       └─ item.unfurl unset → existing 302  [every other QR, unchanged]

q.defcon.run/_og/cherries.png
  → parsePath reserved `_og` branch → 200 image/png (bundled base64), cacheable
```

## Components

- **`lib/unfurl.mjs`** (new): `isCrawler(ua)` regex; `THEMES` registry
  (`cherries` → title/description/image); `resolveTheme(name)`;
  `renderUnfurlHtml({theme, forwardUrl, origin})` (HTML-escaped);
  `loadThemeImageBase64(theme)` (cold-start cached `readFileSync`, defensive → null).
- **`lib/parse-path.mjs`**: reserved `/_og/<theme>.png` → `{kind:"ogimage", theme}`
  (underscore prefix, cannot collide with a mintable code — same guard as `_flush`).
- **`lib/respond.mjs`** (stays pure — no fs): `buildUnfurl({html})` → 200 html
  `no-store`; `buildOgImage({base64})` → 200 png `isBase64Encoded`, `max-age=86400`.
  Export existing `withRegion` so `resolve` can region-prefix the forward URL.
- **`lib/resolve.mjs`**: in the `redirect` branch, if `item.unfurl` resolves to a
  theme **and** `isCrawler(ua)` → render + `buildUnfurl` (forward = pre-enrich
  `destination` via `withRegion`, **no query**). New `ogimage` branch. Both new
  branches emit **no scan log** (crawler prefetch / asset fetch aren't scans).
  Any failure still degrades to `302`/`404` — the never-throw invariant holds.
- **Asset**: `apps/run.qr/lambda/resolver/assets/cherries-og.png`, 1200×630,
  generated by Playwright-screenshotting a neon-cherries HTML card. Zipped into
  the Lambda by the existing `archive_file` step.
- **Entity**: add optional `unfurl: {type:"string"}` to the `Qr` entity in both
  `apps/run.qr/lambda/resolver/lib/entities.mjs` and
  `apps/run.human/webapp/src/entities/qr.ts`.
- **run.human admin**: an "Unfurl preview" select (None / 🍒 Cherries) on the
  admin QR edit surface that persists `unfurl`. This is the reusable opt-in. The
  existing `C` code is set to `cherries` so `/c` lights up immediately.

## Visual

Electro-fluorescent slot machine: near-black background, three glowing red
cherries on a spun reel, neon magenta/cyan glow, chrome "JACKPOT — FLAG CAPTURED"
lockup, DEF CON run mark. **No code shown.** Static PNG is the preview card; the
same CSS art backs the (rarely-seen) crawler HTML body.

## Security / robustness

- **Secret-safe**: og tags and the crawler-facing forward URL never carry `v`.
  The `og:image` is a static PNG. Only the human `302` carries the code.
- **Injection**: `renderUnfurlHtml` HTML-attribute-escapes every interpolated URL
  (destination is operator-controlled) and `<`-escapes the JS string form.
- **Never throws**: unfurl/og-image paths are wrapped by `resolve`'s existing
  try/catch and each helper degrades to `null` → falls back to `302`/`404`.

## Testing

- Resolver vitest: `isCrawler` UA matrix; crawler+unfurl → HTML (asserts og tags,
  no `v`); human+unfurl → `302` (with `v`); non-unfurl → `302`; `/_og/cherries.png`
  → png; unknown theme → `404`; forced-error → `302`/`404` fallback; HTML-escaping.
- Post-deploy UAT: paste `q.defcon.run/c?v=TEST` into Slack + opengraph.xyz.

## Deploy

Two normal deploys: **qr-resolver terragrunt** (resolver + bundled PNG) and
**run.human** (entity field + admin select). No schema migration — just flip the
one `C` item.

## YAGNI / follow-ups

- Only the `cherries` theme now (registry ready for more).
- No CloudFront cache behavior for `/_og/*` yet — uncached at crawler volume is
  fine; a `max-age` behavior is a later optimization.
- No bulk DynamoDB migration.
