Create a regional `mqtt/` terragrunt unit in both regions. This unit is a hybrid -- it contains inline Terraform (for S3 buckets) AND invokes the nlb-dns module (for DNS). Because Terraform can only have one `source`, the approach is:

**Option A (recommended): Inline Terraform with module call.** Create `main.tf` directly in the mqtt/ directory containing S3 bucket resources AND a `module "nlb_dns"` call to the nlb-dns module. The terragrunt.hcl wires dependencies and inputs.

**Directory structure per region:**
```
region/{region}/mqtt/
  terragrunt.hcl   # Dependencies, inputs, providers
  main.tf          # S3 buckets + module "nlb_dns" call
  variables.tf     # Input variables
  outputs.tf       # Bucket names, DNS outputs
```

**terragrunt.hcl:**
- Include skip check (same pattern as other regional units): `include "skip" { path = "${find_in_parent_folders("region")}/skip.hcl" }`
- Dependencies: `network` (NLB outputs), `site` or appropriate module that exposes zone_map (the mqtt.defcon.run zone_id)
- Include regional providers: `include "providers" { path = "${find_in_parent_folders("providers")}/regional.hcl" }`
- NOTE: The providers include must expose `aws.global-application` provider alias since nlb-dns module needs it. Check the cloudfront terragrunt.hcl to see how it gets the global-application provider -- the mqtt/ unit needs the same provider configuration. If the regional providers don't include global-application, use the same pattern as cloudfront (which likely uses a different providers include).
- Terraform source should point to local directory since main.tf is inline: `terraform { source = "." }` or similar
- Inputs: wire `site` (label, random_suffix), `region` (label, full), `nlb_dns_name`, `nlb_zone_id`, `zone_id` for mqtt.defcon.run from dependencies

**main.tf:**

S3 blocklist bucket (INFRA-06):
```hcl
resource "aws_s3_bucket" "mqtt_blocklist" {
  bucket = "mqtt-blocklist-${var.region.label}-${var.site.label}-${var.site.random_suffix}"
  tags = {
    Name    = "mqtt-blocklist"
    Service = "run-mqtt"
    Region  = var.region.label
    Site    = var.site.label
  }
}

resource "aws_s3_bucket_public_access_block" "mqtt_blocklist" {
  bucket                  = aws_s3_bucket.mqtt_blocklist.id
  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}
```

S3 logs bucket (INFRA-10):
```hcl
resource "aws_s3_bucket" "mqtt_logs" {
  bucket = "mqtt-logs-${var.region.label}-${var.site.label}-${var.site.random_suffix}"
  tags = {
    Name    = "mqtt-logs"
    Service = "run-mqtt"
    Region  = var.region.label
    Site    = var.site.label
  }
}

resource "aws_s3_bucket_public_access_block" "mqtt_logs" {
  bucket                  = aws_s3_bucket.mqtt_logs.id
  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}

resource "aws_s3_bucket_lifecycle_configuration" "mqtt_logs" {
  bucket = aws_s3_bucket.mqtt_logs.id
  rule {
    id     = "expire-old-logs"
    status = "Enabled"
    expiration {
      days = 30
    }
  }
}
```

nlb-dns module call (INFRA-04):
```hcl
module "nlb_dns" {
  source = "../../../modules/nlb-dns/v1.0.0"

  zone_id      = var.mqtt_zone_id
  domain_name  = "mqtt.${var.dns_zonename}"
  nlb_dns_name = var.nlb_dns_name
  nlb_zone_id  = var.nlb_zone_id
  region       = var.region

  providers = {
    aws.global-application = aws.global-application
  }
}
```

IMPORTANT: The module source path is relative to where terragrunt generates the `.terragrunt-cache` directory. Check how other regional units reference modules -- if they use `include "module"` pattern with config.hcl, this inline approach differs. The correct relative path from the terragrunt cache to modules/ depends on terragrunt's behavior. If terragrunt copies the source to a cache dir, the path must be from cache. If source = "." with local files, terraform runs in-place so the path is relative to the mqtt/ directory.

Look at how the cloudfront module is invoked in the live config for the correct path pattern. The safest approach: use an absolute-ish path via `find_in_parent_folders` or similar terragrunt function, OR use `${path_relative_from_include()}` patterns.
