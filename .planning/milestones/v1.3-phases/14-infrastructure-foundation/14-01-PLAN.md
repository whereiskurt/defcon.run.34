All three must be fixed/created before any MQTT infrastructure can be wired.

  <action>
Create directory `infra/terraform/modules/nlb-dns/v1.0.0/`.

**variables.tf:** Define input variables:
- `zone_id` (string) -- Route53 hosted zone ID for the subdomain (e.g., mqtt.defcon.run zone)
- `domain_name` (string) -- Full domain name for the A record (e.g., "mqtt.defcon.run")
- `nlb_dns_name` (string) -- NLB DNS name from network module output
- `nlb_zone_id` (string) -- NLB hosted zone ID from network module output
- `region` (object with `label` string and `full` string) -- Region info for set_identifier and latency policy

**main.tf:** Create a single `aws_route53_record` resource:
```hcl
resource "aws_route53_record" "nlb_alias" {
  provider = aws.global-application

  zone_id = var.zone_id
  name    = var.domain_name
  type    = "A"

  set_identifier = var.region.label

  alias {
    name                   = var.nlb_dns_name
    zone_id                = var.nlb_zone_id
    evaluate_target_health = true
  }

  latency_routing_policy {
    region = var.region.full
  }
}
```

Key details:
- Uses `provider = aws.global-application` (same pattern as cloudfront/route53.tf -- the subdomain zone lives in the application account)
- `set_identifier = var.region.label` makes each regional record unique (e.g., "use1", "cac1")
- `evaluate_target_health = true` so Route53 stops routing to a region if its NLB health checks fail
- `latency_routing_policy` uses the full region name (e.g., "us-east-1") -- this is what Route53 uses for nearest-region selection

**outputs.tf:** Output the record FQDN and name:
```hcl
output "fqdn" {
  description = "FQDN of the created DNS record"
  value       = aws_route53_record.nlb_alias.fqdn
}

output "name" {
  description = "Name of the created DNS record"
  value       = aws_route53_record.nlb_alias.name
}
```

Also create a minimal `providers.tf` or add a `required_providers` block in main.tf declaring the `aws.global-application` provider alias as required (or use a `terraform { required_providers }` block). Check the cloudfront module for the exact pattern used -- the provider must be passed by the caller, not declared in the module. If cloudfront module does NOT declare it (relying on caller to pass), follow the same convention -- do NOT add a providers block.
