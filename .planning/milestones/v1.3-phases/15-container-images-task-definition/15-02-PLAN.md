Create the meshtk proxy Docker image using multi-stage Go build.

**NOTE:** This Dockerfile lives at `apps/mqtt/meshtk/Dockerfile.meshtk` but during Docker build (Phase 16 build.sh), the build context will be `apps/mqtt/meshtk/` after build.sh copies the meshtk source replacing the symlink. For now, the Dockerfile assumes the meshtk Go source is in the build context root.

**apps/mqtt/meshtk/Dockerfile.meshtk:**
```dockerfile
# Build stage - compile meshtk binary
FROM golang:1.24-alpine AS builder

RUN apk add --no-cache git

WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download

COPY . .
RUN CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -ldflags="-s -w" -o /meshtk ./cmd/meshtk.go

# Runtime stage
FROM alpine:3.21

RUN apk add --no-cache ca-certificates

COPY --from=builder /meshtk /usr/local/bin/meshtk

EXPOSE 1883

HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
  CMD nc -z localhost 1883 || exit 1

ENTRYPOINT ["meshtk"]
CMD ["server", "proxy"]
```

Key design decisions:
- Go version 1.24 matches go.mod (`go 1.24.1`)
- CGO_ENABLED=0 for static binary (no C deps needed for meshtk)
- `-ldflags="-s -w"` strips debug symbols for smaller image
- Health check uses `nc` (netcat from busybox in Alpine) on port 1883
- CMD is `server proxy` — the meshtk proxy mode that intercepts MQTT CONNECT packets
- No `nc` package needed — Alpine's busybox includes it
- The meshtk binary reads its config from environment variables and/or YAML config file passed via CLI flags. ECS will inject env vars via secrets.

**Environment variables consumed by meshtk proxy at runtime (injected via ECS secrets):**
- `MESHTK_MQTT_BROKER_URI` — mosquitto address (tcp://localhost:1884)
- `MESHTK_MQTT_USERNAME` — meshtk-proxy service account username
- `MESHTK_MQTT_PASSWORD` — meshtk-proxy service account password
- `MESHTK_LISTEN_ADDR` — proxy listen address (0.0.0.0:1883)
- `MESHTK_S3_LOGS_BUCKET` — S3 bucket for packet inspection logs
- `MESHTK_S3_BLOCKLIST_BUCKET` — S3 bucket for dynamic blocklist
- `MESHTK_DYNAMODB_TABLE` — run.human DynamoDB table for user credential lookup
- `MESHTK_LOG_INTERVAL` — S3 log rotation interval

The exact CLI flags and config format depend on meshtk's internal implementation. The Dockerfile just builds the binary — ECS task definition (Plan 03) wires the env vars.

Create the nginx/meshobserv combined container. This container runs two processes via supervisord: nginx serving meshmap static HTML, and meshobserv subscribing to MQTT to write nodes.json.

**apps/mqtt/nginx/Dockerfile.nginx:**
```dockerfile
# Build stage - compile meshobserv binary from meshtk source
FROM golang:1.24-alpine AS builder

RUN apk add --no-cache git

WORKDIR /src
COPY meshtk/go.mod meshtk/go.sum ./
RUN go mod download

COPY meshtk/ .
RUN CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -ldflags="-s -w" -o /meshobserv ./cmd/meshtk.go

# Runtime stage
FROM alpine:3.21

RUN apk add --no-cache nginx supervisor curl

# Create directories
RUN mkdir -p /var/www/html /var/log/supervisor /run/nginx

# Copy meshobserv binary (same meshtk binary, different command)
COPY --from=builder /meshobserv /usr/local/bin/meshobserv

# Copy nginx config
COPY nginx/nginx.conf /etc/nginx/nginx.conf

# Copy supervisord config
COPY nginx/supervisord.conf /etc/supervisord.conf

# Copy meshmap HTML from meshtk source (DC33 port)
# The meshmap static files are served by nginx
# NOTE: If meshmap HTML lives in a different location in the meshtk repo,
# the executor should find the correct path. Check for HTML files in:
# - meshtk/web/ or meshtk/static/ or meshtk/meshmap/
# If no meshmap HTML exists in meshtk repo yet, create a placeholder
# index.html with "meshmap coming soon" and a TODO comment.
# Phase 17 will port the actual meshmap HTML from DC33.

EXPOSE 80

HEALTHCHECK --interval=30s --timeout=3s --start-period=15s --retries=3 \
  CMD curl -f http://localhost/ || exit 1

CMD ["/usr/bin/supervisord", "-c", "/etc/supervisord.conf"]
```

**IMPORTANT build context note:** This Dockerfile's build context is `apps/mqtt/` (not `apps/mqtt/nginx/`). This is because it needs access to both `apps/mqtt/meshtk/` (Go source) and `apps/mqtt/nginx/` (config files). The COPY paths reflect this:
- `COPY meshtk/go.mod` — from apps/mqtt/meshtk/
- `COPY nginx/nginx.conf` — from apps/mqtt/nginx/

**apps/mqtt/nginx/supervisord.conf:**
```ini
[supervisord]
nodaemon=true
user=root
logfile=/var/log/supervisor/supervisord.log
pidfile=/var/run/supervisord.pid

[program:nginx]
command=/usr/sbin/nginx -g "daemon off;"
autostart=true
autorestart=true
priority=10
stdout_logfile=/dev/stdout
stdout_logfile_maxbytes=0
stderr_logfile=/dev/stderr
stderr_logfile_maxbytes=0

[program:meshobserv]
command=/usr/local/bin/meshobserv server inspect
autostart=true
autorestart=true
priority=20
startretries=10
startsecs=5
stdout_logfile=/dev/stdout
stdout_logfile_maxbytes=0
stderr_logfile=/dev/stderr
stderr_logfile_maxbytes=0
```

meshobserv runs as `meshtk server inspect` command — this is the mode that subscribes to MQTT topics, decrypts Meshtastic traffic, and writes nodes.json to the filesystem. The binary is the same meshtk binary, just invoked with a different command.

meshobserv auto-restarts on crash (autorestart=true) with up to 10 retries.
nginx has priority 10 (starts first), meshobserv has priority 20 (starts after nginx).

**apps/mqtt/nginx/nginx.conf:**
```nginx
worker_processes auto;
error_log /dev/stderr warn;
pid /run/nginx/nginx.pid;

events {
    worker_connections 256;
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;

    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent"';
    access_log /dev/stdout main;

    sendfile on;
    keepalive_timeout 65;
    gzip on;
    gzip_types application/json text/html text/css application/javascript;

    server {
        listen 80;
        server_name _;

        root /var/www/html;
        index index.html;

        # Serve meshmap static files
        location / {
            try_files $uri $uri/ /index.html;
        }

        # nodes.json is written by meshobserv every 10 seconds
        # Disable caching so browsers always get fresh data
        location /nodes.json {
            add_header Cache-Control "no-cache, no-store, must-revalidate";
            add_header Pragma "no-cache";
            add_header Expires "0";
            # CORS for meshmap polling
            add_header Access-Control-Allow-Origin "*";
        }

        # Health check endpoint
        location /health {
            access_log off;
            return 200 "ok";
            add_header Content-Type text/plain;
        }
    }
}
```

Key points:
- nginx listens on port 80 (plain HTTP) — NLB terminates TLS at 443
- nodes.json has no-cache headers since meshobserv overwrites it every 10 seconds
- /health endpoint for optional internal checks
- worker_connections 256 is sufficient for meshmap (low traffic static site)
- CORS on nodes.json allows meshmap JavaScript to poll from any origin
