# Requirements: DEF CON Run 34 — CMS Content Types

**Defined:** 2026-03-02
**Core Value:** Event organizers can manage DCR34 events, routes, and points of interest through cms.defcon.run with a branded OIDC login experience and working REST API for run.human consumption.

## v1.1 Requirements

Requirements for CMS content types milestone. Each maps to roadmap phases.

### Infrastructure (INFR)

- [x] **INFR-01**: Worker litestream sync script safely handles WAL/SHM files under active read load (no mv-swap corruption)
- [x] **INFR-02**: S3 upload provider uses Strapi 5 config format (v5 `s3Options.credentials` nesting)

### Schema (SCHM)

- [x] **SCHM-01**: Shared coordinates component (lat/lng with -90/90 and -180/180 validation) available for all content types
- [x] **SCHM-02**: Organizer can CRUD Events with title, slug, rich text description, short description, start/end datetime, location name, location coordinates, cover image, photo gallery, file attachments, sort order
- [x] **SCHM-03**: Organizer can CRUD Routes with name, slug, rich text description, short description, route type (P2P/loop/out-and-back), distance, elevation gain, difficulty, estimated duration, GPX files (S3), start/end coordinates, cover image, map styling (color/weight/opacity), sort order
- [x] **SCHM-04**: Organizer can CRUD Points of Interest with name, slug, description, coordinates, POI type, marker image, photo, sort order
- [ ] **SCHM-05**: Events and Routes linked via bidirectional many-to-many relation
- [ ] **SCHM-06**: Routes and POIs linked via bidirectional many-to-many relation
- [x] **SCHM-07**: All content types support draft/publish lifecycle

### Auth UX (AUTH)

- [ ] **AUTH-01**: cms.defcon.run root shows DCR34-branded login, not raw Strapi admin form
- [ ] **AUTH-02**: Login triggers OIDC flow to auth.defcon.run with single sign-in button

### API (API)

- [ ] **API-01**: Published events, routes, and POIs accessible via REST API without authentication (Public role)
- [ ] **API-02**: REST API supports population of relations and media (events->routes, routes->POIs+GPX URLs)
- [ ] **API-03**: REST API supports field selection and filtering (by date, type, slug)

### Client (CLNT)

- [ ] **CLNT-01**: run.human has a reusable CMS fetch client using service discovery to regional CMS workers
- [ ] **CLNT-02**: TypeScript types for Event, Route, POI API responses
- [ ] **CLNT-03**: Rich text blocks renderer configured for CMS content display (following DCR33 pattern)

### Seed Data (SEED)

- [ ] **SEED-01**: Sample DCR34 events seeded (Day 1 Run, Day 1 Social, Day 2 Swag Swap, etc.)
- [ ] **SEED-02**: Sample routes with GPX files and POIs linked to events

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Live race timing / splits | Specialized hardware domain; DCR34 is a fun run, not competitive |
| Participant registration via CMS | Registration belongs in run.human (has user accounts, DynamoDB) |
| Real-time participant tracking | Meshtastic MQTT data in run.human, not CMS content |
| Route editing in CMS admin | gpx.defcon.run (gpx-studio) handles GPX editing |
| GraphQL API | REST with populate/select is sufficient; avoids extra plugin |
| i18n / localization | English only; DEF CON is US-based |
| Complex RBAC per content type | Small organizer team (3-5); all get full CMS access |
| SEO fields | CMS content consumed internally by run.human, not crawled |
| Recurring event scheduling | Only ~10-20 events; manual creation is fine |
