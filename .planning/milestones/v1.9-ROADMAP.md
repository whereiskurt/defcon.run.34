# Milestone v1.9: CMS-Driven UI Copy Catalog

**Status:** ✅ SHIPPED 2026-07-06
**Phases:** 35-39
**Total Plans:** 21

## Overview

Make static UI copy across the apps editable from Strapi without a deploy — a single `ui-string` catalog served through a cached, fallback-safe copy toolkit, edited via a custom three-column admin page, proven first on the bib donate/sponsor surface and then unified across the shared chrome. No Redis, no revalidation webhook — propagation rides the existing master/worker + Litestream topology (eventual, ~15 min via time-based `revalidate:N`). Full design: `docs/superpowers/specs/2026-07-05-cms-copy-catalog-design.md`.

Deferred to v2: MIGR-04 (flash/human/auth/gpx migration), I18N-01 (locale population + switcher).

## Milestone Summary

**Key Decisions:**

- **Words-only scope** — each app keeps its own React header/menu and reads labels by shared `common.*` key; no shared component library.
- **No Redis / no revalidation webhook** — eventual consistency (~15 min) rides the existing master/worker + Litestream topology + time-based `revalidate:300`.
- **Own `locale` column** (not native Strapi i18n) so the three-column admin grid stays flat; only `default` populated in v1.
- **Cached fallback** — the resolver (Strapi → S3 export → committed snapshot) is wrapped in the Next.js Data Cache, so a destroyed CMS never costs a slow failed call per load; the UI never renders a raw dotted key.
- **bib donate/sponsor is the proof surface** — the hardest case (client-side, interpolated, modal-heavy) validated the whole approach; the plane could land after Phase 37.
- **Strapi `locale` query is reserved** — the runtime reader fetches all rows and selects the locale in JS (never `filters[locale][$eq]`, which 400s against our own non-i18n column).
- **Deploy-safe before import** — `resolveCopy` merges `{...snapshot, ...s3, ...strapi}`, so apps ship on the committed snapshot floor before `copy:import` seeds the live catalog; the write-token import only ENABLES live editing, it is not a deploy prerequisite.

**Issues Resolved:**

- SC-3 headline de-dup proven live on prod (2026-07-06): one CMS edit to the shared `common.header.maps` row changed the wording on run.defcon.run in ~2m18s with no deploy and no shared component — then reverted. Operator import lifted the live catalog 64 → 93 keys.
- run.human confirmed clean of the Strapi reserved-`locale` bug (its `copy:import` ran clean against live prod Strapi).

**Issues Deferred (v2):**

- MIGR-04: run.flash / run.human deep surfaces / run.auth / run.gpx copy migration.
- I18N-01: non-`default` locale population + locale switcher (schema is ready).
- Cross-region (cac1) copy convergence unobserved — v1.9 deployed only us-east-1 for the copy-migrated apps, so there was no second live region to observe against; the per-region mechanism is identical and will hold when a 2nd region deploys (N/A, not debt).

**Technical Debt Incurred:**

- None material. Words-only migration touched no infra (no terraform/task-def/env changes on the app side). Both webapps `next build` green; guard suites bib 10/10, human 36/36 (Node v23.6.0 for tests).
