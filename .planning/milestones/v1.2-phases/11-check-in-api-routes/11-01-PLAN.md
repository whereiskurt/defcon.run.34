  <files>apps/run.human/webapp/src/app/api/checkins/route.ts</files>
  <action>
Create `src/app/api/checkins/route.ts` following the meshtastic-radios/route.ts pattern. All four handlers share the same auth preamble: `const session = await auth(); if (!session?.user?.id) return 401`.

**POST handler (API-01):**
- Parse body: `{ samples, source, isPrivate }` (source defaults to "Web GPS")
- Validate GPS samples: must be non-empty array, each sample must have `latitude` (number, -90 to 90), `longitude` (number, -180 to 180), `accuracy` (number), `timestamp` (number). Return 400 with specific message on validation failure.
- Quota: `const tier = getUserTier(session.user.services || ['run']); await requireAndConsumeQuota(session.user.id, 'checkin', 1, tier)` inside try/catch with `handleQuotaError`.
- Privacy default: if `isPrivate` is undefined in request body, look up user's preference via `const user = await getRunUser(session.user.id)` and use `user?.preferences?.checkinPreference === 'private'` (defaults to false/public if no preference set).
- Call `createCheckIn(session.user.id, { source, samples, userAgent: req.headers.get('user-agent') || undefined, isPrivate: resolvedIsPrivate })`.
- After successful create, call `checkQuota(session.user.id, 'checkin', 1, tier)` to get remaining count for response.
- Return 201 with `{ data: checkInItem, quota: { remaining } }`.
- Import `checkQuota` from `@/lib/quota-client` for the remaining count lookup.

**GET handler (API-02):**
- Parse query params: `cursor` (optional string), `limit` (optional number, default 20, cap at 100).
- Call `getCheckInsByUser(session.user.id, limit, cursor)`.
- Return 200 with `{ data: CheckInItem[], cursor: string | null }`.

**PATCH handler (API-03):**
- Parse body: `{ checkinId, isPrivate }` where isPrivate is a boolean.
- Validate: checkinId required (string), isPrivate required (boolean). Return 400 if missing.
- Resolve full composite key: query `getCheckInsByUser(session.user.id, 100)` and find the item where `item.checkInId === checkinId`. If not found, return 404. (This is simpler than a separate index query and the user won't have thousands of check-ins to scan.)
- Call `updateCheckInPrivacy(session.user.id, item.timestamp, checkinId, isPrivate)`.
- Return 200 with `{ data: updatedCheckIn }`.

**DELETE handler (API-04):**
- Parse query param: `checkinId` from URL searchParams. Return 400 if missing.
- Resolve full composite key: same approach as PATCH -- query user's check-ins and find matching checkinId. Return 404 if not found.
- Call `deleteCheckIn(session.user.id, item.timestamp, checkinId)`.
- Return 200 with `{ success: true }`.

**Error handling:** Wrap each handler in try/catch. In POST catch block, check `handleQuotaError(error)` first, then fall through to 500. Other handlers just return 500 on unexpected errors.

**Shared helper:** Extract a `resolveCheckIn(userId: string, checkinId: string)` helper at the top of the file that queries `getCheckInsByUser` and finds the matching item. Used by both PATCH and DELETE. Returns the CheckInItem or null.
