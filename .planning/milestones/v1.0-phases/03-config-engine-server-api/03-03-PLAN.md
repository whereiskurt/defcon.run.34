**Create `src/components/configure/config-pipeline.tsx`** — Four-stage pipeline matching FlashPipeline's visual language.

Per CONTEXT.md locked decisions:
- Four visible stages: MQTT, Channels, Identity, Radio (connecting and committing are internal — don't show as separate pipeline stages)
- Each stage shows category + summary value (e.g., "MQTT: mqtt.defcon.run" → "MQTT: mqtt.defcon.run ✓")
- No secrets shown (no PSK, no MQTT password)
- Real-time speed — no artificial delays

Replicate the FlashPipeline structure:
- `glass-card rounded-xl p-5` wrapper
- Vertical connecting line (absolute left)
- PipelineStage component with icon (left gutter), label + StageIcon inline
- Stage icons: Spinner for active, CheckCircle2 teal for complete, XCircle danger for error, Circle for pending
- Use lucide-react icons: `Radio` for MQTT, `Hash` for Channels, `UserCircle2` for Identity, `Signal` for Radio (or similar appropriate icons)

The component derives StageStatus from ConfigProgress:
- Map the four display stages to the underlying ConfigStage values
- "mqtt" stage: active when progress.stage === "mqtt", complete when "mqtt" in completedStages
- "channels": active when progress.stage === "channels", complete when in completedStages
- "identity": active when progress.stage === "identity", complete when in completedStages
- "radio": active when progress.stage === "radio" || progress.stage === "committing", complete when "radio" in completedStages && "committing" in completedStages

Each complete stage shows its summary from `progress.stageSummaries`:
- MQTT complete label: `"MQTT: ${stageSummaries.mqtt}"` (e.g., "MQTT: mqtt.defcon.run")
- Channels complete label: `"Channels: ${stageSummaries.channels}"` (e.g., "Channels: 2 channels")
- Identity complete label: `"Identity: ${stageSummaries.identity}"` (e.g., "Identity: rabbit_abc1")
- Radio complete label: `"Radio: ${stageSummaries.radio}"` (e.g., "Radio: US / LONG_FAST")

Error message below pipeline (same pattern as FlashPipeline).

**Create `src/components/configure/configure-step.tsx`** — Configure wizard step.

This step auto-starts configuration when it becomes the active step (via useEffect). Per CONTEXT.md: real-time speed, fail entire config on any step failure.

States:
1. **Connecting** (progress.stage === "connecting"): Show "Reconnecting to device..." with Spinner, explain that device is rebooting after flash
2. **Configuring** (any config stage active): Show ConfigPipeline with "Do not disconnect" warning (same as flash step)
3. **Complete** (progress.stage === "complete"): Show ConfigPipeline (all checkmarks) + success card + "Continue" button → advance to Done step
4. **Error** (progress.stage === "error"): Show ConfigPipeline + error card with retry button → goToStepForRetry("connect")

Props:
```typescript
interface ConfigureStepProps {
  configureState: UseConfigureReturn;      // From useConfigure hook
  disconnectTransport: () => Promise<void>; // From serial.disconnect
  onContinue: () => void;                   // advance() from useWizard
  onRetry: () => void;                      // Reset + goToStepForRetry("connect")
}
```

Auto-start: useEffect that calls `configureState.configure(disconnectTransport)` when the component mounts and progress.stage is "idle". Include a ref to prevent double-start.

Success card: glass-card with teal glow (border-teal-500/30, teal shadow), CheckCircle2 icon, "Configuration Complete!" heading, brief description.

Error card: Same pattern as FlashStep error — glass-card with danger border, XCircle icon, error message, recovery steps numbered list. Retry button resets configureState AND calls onRetry (which goes back to Connect step via goToStepForRetry).
