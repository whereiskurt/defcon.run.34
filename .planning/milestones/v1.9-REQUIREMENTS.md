# Requirements: v1.9 CMS-Driven UI Copy Catalog — ✅ SHIPPED 2026-07-06

**Defined:** 2026-07-05
**Shipped:** 2026-07-06
**Core Value:** Participants and organizers have a seamless digital experience for DCR34. This milestone lets organizers change static UI wording live from the CMS — no code change, no deploy — starting with the bib donate/sponsor copy.

**Design spec:** `docs/superpowers/specs/2026-07-05-cms-copy-catalog-design.md`

## v1 Requirements — all complete

### COPY — Catalog data model

- [x] **COPY-01**: Editor can create/edit a UI string as a `(key, locale, value)` row with a `namespace` and optional `notes` — *validated*
- [x] **COPY-02**: `(key, locale)` is enforced unique — no duplicate rows for the same string in the same locale — *validated (lifecycle 4xx guard + DB unique-index backstop)*
- [x] **COPY-03**: The read-only API token exposes `ui-string` find/findOne so app consumers can read the catalog — *validated (200/403 write-deny matrix)*
- [x] **COPY-04**: The `locale` column is multi-lingual-ready; only `default` is populated in v1 — *validated*

### TOOL — Runtime copy toolkit

- [x] **TOOL-01**: `loadCopy(locale)` fetches the catalog from the Strapi API, cached server-side in the Next.js Data Cache (`revalidate:N`) — *validated*
- [x] **TOOL-02**: `t(key, vars)` resolves from a single in-memory merged map with `{placeholder}` interpolation — never a per-element network call — *validated*
- [x] **TOOL-03**: `CopyProvider` / `useCopy` make `t()` available in client components (modals, toasts, handlers) — *validated*
- [x] **TOOL-04**: A copy edit propagates within ~15 min with no deploy (eventual consistency via `revalidate:N` + Litestream) — *validated live 2026-07-06: run.defcon.run/use1 picked up a CMS edit in ~2m18s with no deploy. Cross-region (cac1) N/A — only us-east-1 deployed for copy-migrated apps; mechanism identical per region.*
- [x] **TOOL-05**: Lightweight markdown in a value renders safely client-side — *validated (escape-first, XSS-safe)*

### FALL — Cached fallback & resilience

- [x] **FALL-01**: A Strapi lifecycle hook regenerates an S3 `copy.json` export on any `ui-string` create/update/delete — *validated (master-only; observed regenerate on live import + edit)*
- [x] **FALL-02**: When Strapi is unreachable or a key is missing, the toolkit falls back to the S3 export as the default, and the resolved fallback map is itself cached — *validated*
- [x] **FALL-03**: An optional committed snapshot provides an offline build-time floor for the CMS-and-S3-both-down case — *validated*
- [x] **FALL-04**: The UI never renders a raw dotted key to an end user — *validated live (both apps ran on the snapshot floor pre-import, zero raw keys)*

### ADMN — Custom admin editing

- [x] **ADMN-01**: A custom Strapi admin page shows copy as a three-column table (`label · locale · value`) with inline edit and add-row — *validated (shipped run.cms v0.0.24)*
- [x] **ADMN-02**: The admin page filters by `namespace` — *validated*
- [x] **ADMN-03**: Bulk save upserts rows, enforcing `(key, locale)` uniqueness — *validated*

### MIGR — String migration (bib + shared chrome)

- [x] **MIGR-01**: The bib donate/sponsor surface is fully catalog-driven — the proof surface — *validated*
- [x] **MIGR-02**: Remaining `run.bib` copy is migrated to catalog keys — *validated (Phase 39-04: TransactionHistory→`bib.txn.*`, AdminActions→`bib.admin.*`)*
- [x] **MIGR-03**: Shared chrome copy (`common.header.*`, `common.profileMenu.*`) is migrated so every app reads the same keys — *validated (bib + run.human read identical `common.*` rows; SC-3 de-dup proven live)*

## Out of Scope (as shipped)

| Feature | Reason |
|---------|--------|
| Shared React header/profile-menu component library | Words-only scope — each app keeps its own React and reads labels by shared key |
| Redis / shared Next cache handler | Eventual consistency over master/worker + Litestream accepted |
| `revalidateTag` change webhook + per-app revalidation route | Time-based `revalidate:N` alone converges all regions |
| Strapi `rest-cache` plugin | Caching lives app-side in the Next.js Data Cache |
| GraphQL | REST + field/populate query params sufficient |
| Native Strapi i18n plugin | Own `locale` column for the flat three-column admin grid |
| Strapi blocks for copy | Lightweight markdown in a string field covers rich needs |
| Draft/publish on `ui-string` | Save = live in v1 |
