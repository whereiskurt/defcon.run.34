<objective>
Complete the POI data path. Populate each Strapi route's related `point-of-interest` records in
`strapi.ts` (design §2) and fill Phase 2's empty `CmsRouteData.pois` seam, then nest those POIs
onto every `PublicMap` in the manifest (design §3) — for BOTH standalone CMS routes and
Dynamo-enriched routes — so the studio (plan 03-02) can render them.

This builds directly on Phase 2: `fetchRouteMeta()` already returns `{ byGpxKey, cmsRoutes }`,
every `CmsRouteData` already declares `pois: PoiMeta[]` (currently always `[]`), and the manifest
`PublicMap` already carries the optional `pois?` seam. This plan ONLY fills those seams — it does
not re-plan Phase 2's filter/populate/emission work (assume it shipped). The two files are one data
contract, so they are planned and executed together.

Purpose: Deliver POIs (coordinates + marker/photo media + type) to the manifest so a CMS-authored
route's POIs travel with it.
Output: `pointsOfInterest` populate + filled `pois` in `strapi.ts`; per-route `pois` attachment in
the manifest. No build/deploy (release is separate).
</objective>

- scalar fields `name`, `description`, `poiType`, `sortOrder`
  (e.g. `populate[pointsOfInterest][fields][0..]=name,description,poiType,sortOrder`);
- the `coordinates` COMPONENT's `latitude` + `longitude`
  (`populate[pointsOfInterest][populate][coordinates][fields][0]=latitude`, `[1]=longitude`);
- the `markerImage` media `url` (`populate[pointsOfInterest][populate][markerImage][fields][0]=url`);

Fill pois — in the per-row loop, read the row's `pointsOfInterest` array and map each POI to a
`PoiMeta` (the interface Phase 2 already declared — reuse it, do NOT redeclare):
- `name` from the POI `name`;
- `description` from the POI `description` (a plain `text` string — pass through as-is, do NOT run it
  through `blocksToHtml`; it is escaped at render time by the studio in plan 03-02);

- `poiType` from the POI `poiType` enum string;
- `markerImageUrl` from `markerImage.url` (undefined when no marker image);
- `photoUrl` = `photo.formats.small?.url ?? formats.medium?.url ?? formats.thumbnail?.url ?? photo.url`
  (undefined when no photo) — mirror the existing `coverImageDisplayUrl` sizing logic;
- `sortOrder` from the POI `sortOrder`.
Sort the resulting `PoiMeta[]` by ascending `sortOrder` (treat missing as 0) and assign it to the
`CmsRouteData.pois` for that row (replacing the `[]` placeholder). Rows with no `pointsOfInterest`
keep `pois: []`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Strapi CMS (trusted editors) → run.gpx server (`fetchRouteMeta`) | POI records (coordinates, description, media URLs) are read over the internal Bearer call; only published rows/relations are read. |
| run.gpx `/api/gpx/public/maps` → public/unauthenticated clients | POI fields are folded into the public manifest and must expose only published, safe values (URLs, plain text). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Information Disclosure | `pointsOfInterest` populate status | medium | mitigate | The `status=published` root filter is preserved so draft/unpublished POIs never reach the unauthenticated manifest; POI `markerImageUrl`/`photoUrl` are already-public CloudFront (`cms.defcon.run`) assets — no presigned-credential leak. |
| T-03-02 | Cross-Site Scripting | POI `name`/`description` folded into the manifest | medium | mitigate | POI `description` is a plain Strapi `text` field passed through as a string (NOT raw HTML, no `blocksToHtml`), and `name`/`description`/`photoUrl` are escaped at render time by the studio (`escapeHtml`, plan 03-02). This plan introduces NO raw-HTML passthrough. |
| T-03-03 | Tampering | POI coordinates from CMS | low | accept | Coordinates are numeric-guarded (`num`) and a POI with missing/non-finite lat/lon is skipped, so a malformed coordinate cannot inject a NaN marker into the manifest. Values are authored by trusted editors. |

No package-manager installs in this plan — no supply-chain (T-*-SC) threat applies.
</threat_model>
