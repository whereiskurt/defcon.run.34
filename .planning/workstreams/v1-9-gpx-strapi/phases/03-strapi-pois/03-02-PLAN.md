`gpx-layer.ts` is needed — `getSvgForSymbol(symbol, layerColor?, pinColor?)` already accepts a symbol
+ route color.

with the route.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Studio browser (`gpx.{zonename}`) → CMS media CloudFront (`cms.{zonename}`) | The POI `markerImage` is loaded cross-origin as a map image; without CORS it would taint the canvas. |
| Manifest POI fields (`name`, `description`, `photoUrl`) → rendered popup DOM | Editor-authored text/URLs are injected into popup HTML in the studio. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-04 | Tampering (canvas taint) | `map.addImage` from cross-origin CMS `markerImage` (Risk 3) | medium | mitigate | `loadUrlImage` sets `crossOrigin='anonymous'` and relies on the CMS-media CORS added in Phase 2 (02-03); on any load failure/taint it falls back to the poiType SVG default so a POI is never left blank. The popup `photo` uses a plain `<img>` (no canvas) and is unaffected. |
| T-03-05 | Cross-Site Scripting | POI `name`/`description`/`photoUrl` in the popup HTML | medium | mitigate | All three are passed through `escapeHtml` before insertion; the `description` is plain CMS text (never treated as HTML). No `innerHTML` raw passthrough is introduced. |
| T-03-06 | Spoofing | Marker image URL as an arbitrary cross-origin resource | low | accept | `markerImageUrl` originates from a trusted-editor CMS media field served from `cms.defcon.run`; it is loaded as an image only (not executed). A hostile URL at worst fails to load and triggers the poiType fallback. |

No package-manager installs in this plan — no supply-chain (T-*-SC) threat applies.
</threat_model>
