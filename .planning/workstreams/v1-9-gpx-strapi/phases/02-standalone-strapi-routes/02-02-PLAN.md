<objective>
Turn Strapi from an enrichment-only right-join into ALSO a left source of routes. Widen the
run.gpx Strapi client to fetch CMS-native routes (which may have no `gpxFileId`) and return their
GPX asset + placement metadata, then emit each standalone route into the public manifest as a
first-class `PublicMap` folded into its `mapFolder` group — while a route that collides with an
existing GLOBAL DynamoDB route stays enrichment-only (DynamoDB wins, no double-render).

Implements detailed design §2 (`strapi.ts` / `fetchRouteMeta`) and §3 (manifest / `route.ts`) and
decisions D1, D2, D3, D4. The two files are ONE data contract, so they are planned and executed
together. POI populate/attach is explicitly deferred to Phase 3 — this plan only leaves the
extension points (`PoiMeta` interface and an empty `pois` seam); it does NOT populate POIs.

Purpose: Make a fully CMS-authored route appear on the public map with no run.gpx upload / DynamoDB
round-trip.
Output: Widened `fetchRouteMeta()` with a new two-part return shape; manifest standalone-route
emission + grouping + collision handling. No build/deploy (release is separate).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Strapi CMS (trusted editors) → run.gpx server | `fetchRouteMeta()` reads CMS routes over an internal Bearer-token call; only published rows are read. |
| run.gpx `/api/gpx/public/maps` → public/unauthenticated clients | The manifest is served to anyone; it must expose only published, public content and safe URLs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-03 | Information Disclosure | `fetchRouteMeta()` status filter | medium | mitigate | Preserve `status=published` so draft/unpublished CMS routes never reach the unauthenticated manifest. The CMS media `downloadUrl` is an already-public CloudFront asset (no presigned-URL/credential leak). |
| T-02-04 | Cross-Site Scripting | CMS fields folded into the manifest (`descriptionHtml`, `title`, `gpxName`) | medium | mitigate | Keep `blocksToHtml` sanitization (escapes every text node + href) as the only HTML source; title/gpxName/fileName are escaped at render time by the studio (`escapeHtml`). Introduce NO raw HTML passthrough in this plan. |
| T-02-05 | Spoofing / Tampering | Synthetic `cms-{documentId}` fileId + collision handling | low | mitigate | `cms-` namespacing prevents a CMS record from masquerading as (or being confused with) a DynamoDB UUID route; the `dynamoKeys` collision skip guarantees a CMS record can never override or double-render a real DynamoDB route's geometry (DynamoDB wins, D2). |
| T-02-06 | Denial of Service / Availability | Strapi slow or unavailable | low | mitigate | Best-effort semantics retained (2500ms abort + try/catch + empty `cmsRoutes`), so the manifest degrades to DynamoDB-only rather than failing. |

No package-manager installs in this plan — no supply-chain (T-*-SC) threat applies.
