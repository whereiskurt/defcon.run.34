<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bib client → run.human (deep links) | User-initiated navigation to public run.defcon.run URLs; no secrets, no request body |
| bib client → cms.defcon.run / bib /admin | Menu items are UX affordances; the target apps enforce authorization server-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-34-05-01 | Information Disclosure | run.human deep links (Profile/Check-in/QR) | low | accept | Links carry only a path + `?open=checkin|qr` — no tokens, hash, or PII in the URL; region segment is non-secret. No secret is ever placed in a link. |
| T-34-05-02 | Elevation of Privilege | CMS / Admin dropdown items | low | mitigate | Items render only when `session.services` includes the matching group — same client-side gating pattern already shipped. This is UX-only; cms.defcon.run and the bib `/admin` route remain the real authorization boundary (server-enforced), so a spoofed client that force-renders the item still hits a server 401/403. |
| T-34-05-03 | Tampering | new-tab deep links | low | accept | HeroUI DropdownItem href navigation opens a fixed same-origin-family host (run.defcon.run); no `window.opener` reverse-tabnabbing risk of note for these first-party targets. No third-party or user-controlled URL is constructed. |
</threat_model>
