(empty) bibs from totals + roster, and add two inline organizer actions — reconcile a

a manual payment or reset a bib. Implements CONTEXT decisions D-01…D-04 (A-T1…A-T4).

`AdminActions` client component wired into the existing dark-theme admin tables.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/admin/bib/{reconcile,reject} | Untrusted client input crosses into privileged mutations (payment apply, bib delete, quota restore) |
| run.bib server → run.auth quota service | Server-to-server call carrying AUTH_INTERNAL_SECRET |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-34-01 | Spoofing/Elevation | reconcile + reject routes | high | mitigate | `requireAdmin(await auth())` → 401 no_session / 403 not_admin before any work (D-02, D-04) |
| T-34-02 | Tampering | reconcile body | high | mitigate | zod safeParse: kind/provider enums, `amountCents` int().positive(), string pendingId/ownerSub → 400 on fail |
| T-34-03 | Repudiation/Tampering | reconcile double-count | medium | mitigate | per-kind idempotency: bib dedupes on `reconciled_via = admin_manual_<pendingId>` (applyPayment); donation dedupes on its PK `donationId = admin_manual_<pendingId>` (recordDonation ConditionalCheckFailed → read-back) |
| T-34-04 | Denial/Elevation | reject deletes ownerSub | medium | mitigate | admin-gated; ownerSub is Bib PK exposed only on the admin-only page; quota reset wrapped in try/catch so failure can't wedge the delete path |
| T-34-05 | Information disclosure | quota-client internal secret | medium | mitigate | AUTH_INTERNAL_SECRET read server-side only; never logged; body/secret excluded from console output |
| T-34-SC | Tampering | npm installs | low | accept | No new packages introduced (zod already present); no supply-chain surface this plan |
</threat_model>
