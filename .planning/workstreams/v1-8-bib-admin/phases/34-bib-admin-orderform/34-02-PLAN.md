<objective>
Slice C backend. Extend run.human's internal user endpoint to additively return the
runner's `hash`, and add a run.bib server-side lib that resolves that hash and builds the
social-QR URL — with a null-safe fallback so a QR miss never breaks the orderform.

Purpose: The bib tear-off QR should encode the runner's real per-user social-QR value
(run.human profile "Show My QR"). The hash is stored only on run.human's RunUser and is
NOT derivable from session claims, so run.bib must fetch it. Implements D-10 (C-T1, C-T2).
Output: the added `hash` field, `social-qr.ts` (`getSocialQrHash` + `buildSocialQrUrl`),
and a unit test for the URL builder + fallback selection. No shared orderform files touched
here, so this runs in parallel with Slice A and the orderform core.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| run.bib server → run.human internal user endpoint | Server-to-server fetch carrying X-Internal-Secret to read a runner's hash |
| external client → run.human internal endpoint | The endpoint is internal-secret gated; must not leak secret RunUser fields |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-34-05 | Information disclosure | run.human internal user JSON | high | mitigate | Add ONLY `hash` (a lookup value already used in public /r QR URLs); never expose `seed`/`rsaprivSHA`/`rsapubSHA`; existing X-Internal-Secret gate unchanged |
| T-34-06 | Information disclosure | run.bib → run.human fetch | medium | mitigate | AUTH/HUMAN internal secret read server-side only, sent as header, never logged; fixed service-discovery host (no user-controlled URL → no SSRF) |
| T-34-07 | Denial of Service | orderform hash fetch | medium | mitigate | getSocialQrHash catches all errors → null; orderform falls back to runner-code QR; a miss/timeout never 500s the page |
| T-34-SC | Tampering | npm installs | low | accept | No new packages; social-qr uses global fetch + existing env only |
</threat_model>
