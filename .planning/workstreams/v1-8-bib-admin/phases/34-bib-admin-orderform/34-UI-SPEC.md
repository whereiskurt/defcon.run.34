# Phase 34 — UI Design Contract

> Visual and interaction contract for Phase 34 (Bib admin, orderform UX & social QR).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Brownfield contract.** `apps/run.bib/webapp` has an established design system
> (HeroUI + Tailwind 4 + inline-style dark-theme tiles). This spec anchors every new
> surface to the tokens already in the codebase — it does NOT introduce a new system.
> All 10 decisions in `34-CONTEXT.md` are locked and treated as final; where CONTEXT
> left a visual detail open, this spec picks the value most consistent with the
> existing run.bib design and flags it **[discretion]**.

## Spacing Scale

Canonical 4-point scale for all NEW layout (the responsive checkbox wrapper, admin
action rows):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/label gaps, stacked hint spacing |
| sm | 8px | Compact element spacing, input↔button gap |
| md | 16px | Default element spacing |
| xl | 24px | Form section gap (existing BibForm `gap: 24`) |
| 2xl | 32px | Admin section stack (`gap: 32`) |
| 3xl | 48px | Page top padding (admin `padding: 48px …`) |

**Responsive checkbox wrapper (new, Tailwind — SC34.4):**
- Container: `grid gap-5 sm:grid-cols-2` (single column mobile, 2-col ≥640px).
- DOM order: `Sponsor → WillPayInPersonCheckbox → Donate`.
- Checkbox cell: `order-2 sm:order-3 sm:col-span-2` → sits BETWEEN the two tiles on
  mobile, spans FULL WIDTH BELOW both on desktop.
- Tiles keep their existing inline styles; ONLY this wrapper migrates to Tailwind
  (inline styles cannot express the `sm:` breakpoint — CONTEXT decision 6).

**Exceptions (do not "fix" — preserve house style):**
- **20px — tile grid gap (`gap-5`).** Off the canonical 4pt set but LOCKED by the
  CONTEXT task plan (B-T1: `grid gap-5 sm:grid-cols-2`). Justification: it matches the
  existing orderform tile grid's current 20px gutter, preserving visual continuity with
  the unchanged inline-styled Sponsor/checkbox/Donate tiles this wrapper contains. Sits
  between the two adjacent canonical values (16px and 24px). Do not change the value.
- Existing inline-style tiles and `/admin` use non-8pt legacy steps (6, 10, 14, 96px).
  These are preserved as-is in unchanged code; new code should prefer the scale above.
- **Bib SVG geometry is in SVG user-units, NOT the px scale.** QR badge enlarges
  `76 → 112` user-units and stub QR `x/y` reposition are print-layout constants
  (SC34.8), exempt from the spacing scale. Constraint: enlarged QR must render fully
  inside each tear-off stub without overlapping the number boxes or smiley badges.

## Typography

House scale (system stack) — exactly **4 sizes**. New/changed surfaces MUST use these
roles — no new sizes.

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Hint / caption | 13px | 400 | 1.5 | Save-state hints, table cells, note text |
| Body / label | 15px | 600 | 1.5 | Checkbox label, section labels |
| Section heading | 19px | 800 | 1.2 | Admin `ReportSection` `<h2>` |
| Page heading | 30px | 800 | 1.2 | Admin page `<h1>` |

**Legacy exceptions — preserve as-is, do not use in new code:**
The existing orderform form controls already ship two off-scale sizes. They stay
untouched in unchanged code; do NOT adopt them on any new surface (mirrors the Spacing
Exceptions block).
- **14px — existing form labels** (BibForm label text). House value in unchanged code.
- **16px — existing input field text** (orderform inputs). House value in unchanged
  code; also the iOS "no-zoom-on-focus" floor, so it must not be reduced.

New/changed surfaces use only the 4-size scale above (13 / 15 / 19 / 30px).

**Weights:** two primary — **regular 400** (body/hints) and **semibold/bold 600–800**
(labels, buttons, headings). Exception: the **bib SVG render uses weight 900 (Arial
Black)** for the number/name/stamps — print-faithful, SVG-only, out of scope for the
UI weight budget.

**Admin action typography (match existing controls):**
- Approve button label: 13px / weight 700 (matches "Download CSV" pill).
- Amount input: 13px monospace (matches table cells; cents-int discipline).
- Reject button label: 13px / weight 700.

## Color

Dark-theme palette already in the codebase. The **DC34 mint `#6CCDB8`** is the single
brand accent across run.bib; `#00d4aa` is its Vegas-chrome sibling (nav/glow) and is
NOT introduced by this phase.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0a0a0a` / `#0a0a0f` | Page background, admin `<main>` |
| Secondary (30%) | `#12121a` (sections/cards), `#1a1a24` (checkbox tile) | Surfaces, panels, roster rows |
| Borders | `#24242e` / `#2a2a34` | Card + control borders |
| Text primary | `#e4e4ef` | Body copy, headings |
| Text muted | `#a4a4b8` / `#8f8fa8` | Notes, table headers, hints |
| Accent (10%) | `#6CCDB8` | See reserved-for list |
| Destructive | `#ff8a8a` (text/border on dark), `#B91C1C` (Reject fill option) | Reject action, error hints only |
| Positive | `#7fdc9e` | "Saved." confirmation only |
| Warning | `#f4c680` | Low-quota hint only |

**Accent `#6CCDB8` reserved for (explicit list — never "all interactive elements"):**
1. Primary/positive action affordances: orderform **Save** button (enabled), admin
   **Approve** (reconcile) button, "Download CSV" pill.
2. Save-button **glow ring** when the name is dirty (unsaved state, SC34.5).
3. Totals-strip numeric values (existing).
4. Sponsor **PAID! THANK YOU!** stamp lineage (`#3a8f79` fill is the print-safe
   darker mint — unchanged).
5. ALTCHA overlay Spinner tint.

**Destructive is reserved for the Reject action and error hints ONLY.** Approve is a
positive/mint action; Reject is the only destructive control in this phase.

**UNSAVED stamp color [discretion]:** CONTEXT decision 7 says "amber/red" and requires
it to be visually distinct from the green PAID stamp in the same slot. Spec:
saturated red-orange rubber stamp — **fill `#C2410C`**, stroke `#ffe9df`, text `#fff`,
rotated identically to the PAID stamp (`rotate(-11 806 208)`). Reads as alarm/attention
against the white bib and never reads as the green "paid" charm.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — reconcile (admin) | **Approve** (button; sits beside an editable amount input prefilled from the intent's `amountCents`) |
| Primary CTA — save (orderform) | **Save** (existing; glows + enlarges while dirty) |
| Destructive CTA — reject (admin) | **Reject** |
| Destructive confirmation | Native `window.confirm()`: `Reject this bib? This deletes the bib and pending payments and resets the runner's name-change quota. Donations are kept.` → on OK, `POST /api/admin/bib/reject`, then `router.refresh()`. |
| ALTCHA overlay | **Checking you're human…** (HeroUI `<Spinner label="Checking you're human…" />`) — replaces ALL inline "verifying" text |
| Unsaved stamp (bib preview) | **UNSAVED** (rubber stamp; outranks PAID while `dirty`) |
| Empty state — admin roster | `No registrations yet.` (existing; now only shows *registered* bibs — empty visit-created bibs are filtered per SC34.1, so the roster no longer lists phantom rows) |
| Empty state — outstanding | `Nothing outstanding.` (existing) |
| Error — reconcile/reject failure | Surface inline near the action button: `Couldn't apply — try again.` (action stays clickable; no `router.refresh()` on failure) |
| Error — save (orderform) | `Save failed ({detail}) — try again.` (existing `SaveStateHint`, kept) |
| Social-QR fallback (silent) | No user-facing error. When run.human `hash` is unavailable, `BibPreview` silently renders the runner-code QR — the bib NEVER shows a blank stub (SC34.8). |

**Accessibility — single-word CTA labels:** the admin action buttons render a single
verb, so they carry explicit aria-labels for screen-reader clarity:
`aria-label="Approve payment"` on **Approve** and `aria-label="Reject bib"` on
**Reject**. (Visible text stays the single word; the aria-label supplies the object.)

**Copy to REMOVE (SC34.7):**
- BibForm `SaveStateHint` "Checking you're human… (~5s)" branch → deleted (overlay
  replaces it). Keep `saved` / `error` / `quota` / `locked` / rename-count states.
- WillPayInPersonCheckbox PoW "Saving…" hint is now covered by the overlay.

## Interaction Contracts (phase-specific)

These are the interaction/state contracts the executor must implement. Anchored to the
named components in `34-PATTERNS.md`.

### IC-1 · Unsaved state (SC34.5)
- **Trigger:** `dirty = name !== savedName` in `BibForm`.
- **Save button (dirty):** add glow + enlarge. Glow ring in `#6CCDB8`
  (e.g. `box-shadow: 0 0 0 3px #6CCDB855, 0 0 16px #6CCDB8AA`); grow padding
  `10px 16px → 12px 22px` and font `13 → 15px`. **[discretion]** exact shadow values.
  Revert to the base style when clean. Optional `framer-motion`/CSS pulse — MUST be
  gated by `@media (prefers-reduced-motion: reduce)`.
- **Bib preview stamp:** pass new `dirty` prop to `BibPreview`; render an **UNSAVED**
  stamp in the SAME slot/transform as the `sponsor-charm` (PAID) group. **Priority:
  if `dirty` → show UNSAVED and HIDE PAID; else if `hasSponsored` → show PAID.**

### IC-2 · ALTCHA blur overlay (SC34.7)
- **Store:** `lib/altcha-overlay.ts` in-flight counter (`begin`/`end`/`subscribe`),
  driven from `solveAltcha` (`begin()` at entry, `end()` in `finally`).
- **Overlay:** new `components/AltchaOverlay.tsx`, mounted ONCE in `providers.tsx`
  inside `HeroUIProvider`. When count > 0: fixed full-viewport layer,
  dimmed `rgba(10,10,15,0.55)` + `backdrop-filter: blur(6px)`, centered HeroUI
  `<Spinner label="Checking you're human…" />`. **Non-dismissable** (blocks
  interaction, no close affordance); auto-hides when count returns to 0.
  `framer-motion` fade ~150ms **[discretion]**; z-index above all app chrome
  (e.g. `9999`, above CashRain's `z-index: 5`).

### IC-3 · Responsive checkbox + cash-rain bridge (SC34.4)
- Layout per Spacing section (grid + order utilities).
- Checking "$20 in person" STILL hides the Sponsor tile (`hideBuyBib`, unchanged —
  decision 5).
- Cash-rain now crosses component boundaries: `lib/rain-store.ts` singleton
  (`setRaining`/`subscribe`, mirrors `pending-bib-save.ts`). Checkbox
  `onCheckedChange → setRaining`; `BibForm` subscribes and passes `raining` to
  `<CashRain>`. Cash-rain visual + `prefers-reduced-motion` handling unchanged.

### IC-4 · Admin inline actions (SC34.2, SC34.3)
- New `components/AdminActions.tsx` (`"use client"`), styled to match existing
  `admin/page.tsx` controls (dark theme; `apiBase()` prefix on fetch URLs).
- **ReconcileAction:** editable amount `<input>` (dark field, 13px monospace,
  prefilled from row `amountCents`) + **Approve** button (mint pill, matches
  "Download CSV"; `aria-label="Approve payment"`). On success → `router.refresh()`.
  Wired into Outstanding-table `source==="pending-intent"` rows.
- **RejectAction:** **Reject** button (destructive treatment: `#ff8a8a` text or
  `#B91C1C` fill **[discretion]**, visually secondary to Approve;
  `aria-label="Reject bib"`) → `confirm()` →
  POST → on ok `router.refresh()`. Wired into "All registrations" roster rows.
- Both: on failure, show inline error text, do NOT refresh.

### IC-5 · Enlarged social QR (SC34.8)
- `BibPreview` gains `socialQrUrl?: string`. In each tear-off stub, encode
  `socialQrUrl` via the existing vector `QrBadge` when present, else fall back to
  `runnerCode`. Enlarge badge `76 → ~112` SVG units and reposition the two stub QR
  `x/y` so the larger badges sit fully inside the stub area without overlapping the
  number boxes or smiley badges. Keep the crisp vector renderer (print-safe).
