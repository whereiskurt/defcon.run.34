## Design shift captured (2026-07-02)

Kurt reshaped the payment model mid-Phase-22. Key deltas:
1. **Bib registration is FREE.** Print gate simplifies from `paidAmount >= 1000 && nameLocked` to just `nameLocked`. Everyone who registers by deadline gets name printed.
2. **Payment becomes orthogonal** — sponsors this bib, general donation, or neither.
3. **Two Stripe products**: `donation_type=bib` (attached to a bib) and `donation_type=general` (standalone; anonymous OK).
4. **New Bib field `willPayInPerson`** — persistent flag orthogonal to payment. Doesn't affect print gate.
5. **Admin report** for pledged-but-unpaid.
6. **Naming sweep** — "DEF CON" → "defcon.run" everywhere in copy (keep the smiley graphic symbol).
7. **Sponsor charm accent** on BibPreview when the user has sponsored anything.

## Design gaps flagged

1. **Anonymous general donation** — MVP requires session for auditability. Truly anonymous flow (no login → Stripe redirect → bank a payment) would need a session-less `/api/checkout/general` variant. Deferred; called out in Task 22-05-03 body.
2. **Venmo/CashApp for general donation** — the Haiku matcher (Plan 22-04) currently assumes BIB-XXXX code OR sender→bib lookup. General donations via Venmo/CashApp with no BIB code + no sender-in-bibs match would hit `unmatched`. Working as intended for MVP; a future v1.6 "general donation via Venmo/CashApp" path would need a distinct matcher fallback.
3. **Admin gate choice pending** — Task 22-05-07 proposes Option A (SSM allowlist) as default; executor should confirm at run time if Kurt has a preference by then.
4. **Sponsor charm visual** — a plain star/diamond glyph is the placeholder. Kurt may want a specific icon (e.g., defcon.run wordmark badge) — executor uses geometric default absent guidance.
