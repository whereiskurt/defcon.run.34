    ```typescript
    /** Meshtastic UF2 filename convention: firmware-{platformioTarget}-{version}.uf2 */
    export function getUf2Filename(device: DeviceHardware, version: string = FIRMWARE_VERSION): string {
      return `firmware-${device.platformioTarget}-${version}.uf2`;
    }

    /**
     * Load a UF2 firmware artifact as raw bytes (Uint8Array — DFU write consumes bytes directly,
     * no need for the binary-string dance loadFirmware does for esptool-js).
     * @throws Error if the file is not present under /firmware/ (Dockerfile Stage 1 didn't extract it).
     */
    export async function loadUf2(
      device: DeviceHardware,
      version: string = FIRMWARE_VERSION
    ): Promise<{ data: Uint8Array; size: number; filename: string }> {
      const filename = getUf2Filename(device, version);
      const url = `${FIRMWARE_BASE_PATH}/${filename}`;
      const response = await fetch(url);
      if (!response.ok) {
        throw new Error(
          `UF2 firmware not found for ${device.displayName}. ` +
          `Expected file: ${filename} (HTTP ${response.status}).`
        );
      }
      const buffer = await response.arrayBuffer();
      const data = new Uint8Array(buffer);
      return { data, size: data.length, filename };
    }
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → app bundle | If the library route is chosen in Task 1, a new package enters the client bundle. |
| Web USB → app | `navigator.usb.requestDevice()` accepts a physical device; the `.uf2` bytes come from the same CloudFront-served `public/firmware/` scope as the ESP32 `.factory.bin` set. |
| `.uf2` binary → device | Attacker with write access to `public/firmware/` could ship a malicious `.uf2`. Bounded by the same trust posture as `.factory.bin` — CI-built, image-vendored, no runtime mutation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24.2-01 | Tampering | `.uf2` binary served from `/firmware/` | accept | Same trust posture as `.factory.bin` (v1.4 shipped). Both are baked into the Docker image at build time; runtime cannot substitute them. |
| T-24.2-02 | Denial-of-service | Malformed `.uf2` triggers unrecoverable DFU state | mitigate | Post-write `dfuVerify` reads `DFU_GETSTATUS`; a stuck `dfuERROR` state throws with an actionable message. User can unplug/replug the T-1000E to reset the bootloader. |
| T-24.2-03 | Elevation of privilege | Untrusted page calls `navigator.usb.requestDevice` | mitigate | Web USB requires a user gesture per browser policy — CONTEXT-mandated (Plan 24-01 already established this at the router boundary; useDfu.connect preserves it). |
| T-24.2-04 | Information disclosure | DFU library embeds telemetry/CDN URL | mitigate | Task 1 offline-clean audit grep. DPLY-06 grep gate at Stage 2 continues to fail the build if `api.meshtastic.org` or `github.com/meshtastic` strings leak. |
| T-24.2-SC | Tampering | npm supply chain — DFU library | mitigate | Task 1 `supply_chain_gate` (blocking legitimacy verification before install). Fallback: custom DFU 1.1 client (zero-dependency, ~300 LOC) if all candidates fail. |
