<objective>
Deploy the `/a/<nonce>` resolver change and prove — with a real before/after contrast —
that it did not shadow any live short code.

The regression guard is MANDATORY and non-negotiable. It is exactly how the `/c/`
collision was caught during design: `q.defcon.run/c` is a LIVE short code resolving to
`didhtp1`, and `b c d f g h p r` are all taken. A reserved-letter change that quietly
swallowed one of those would break a live con artifact with no error anywhere.

The resolver ships via its OWN terragrunt unit and is independent of the app image
releases, so it deploys early — any regression surfaces before the bigger release.

Purpose: catch a namespace collision while it is still cheap.
Output: a committed, re-runnable probe script plus a captured pre/post contrast.
</objective>

Write a small committed shell script that probes the live resolver and prints one
machine-comparable line per target: the path, the HTTP status, and the Location header.

Cover three groups:
- the eight live single-letter codes, lowercase as a user would type them;
- the award namespace: a bare reserved letter (expect 404), and a reserved letter
  followed by a sample token (expect a 302 whose Location is the run.defcon.run claim
  page carrying that token as the nonce query parameter).
- ⭐ **the UPPERCASE award letter**: `/A/probe` must ALSO 302 to the claim page, not 404.
  72-01 was amended (W5) to match the reserved letter case-insensitively, because the
  realistic failure is a player reading the award URL off a radio screen and typing it
  into a phone, where mobile keyboards autocapitalize. `/a/` and `/A/` must behave
  identically; the NONCE stays verbatim (the claim page lowercases that half).
  A 404 here means the W5 fix did not deploy.

Use a bounded per-request timeout and follow NO redirects — the Location header is the
assertion target, and following it would hit the claim page and could park a cookie.
Emit stable, sorted, diffable output so a pre/post `diff` is meaningful. Do not use
`--max-time` as the only guard on a body read; this script reads headers only.

Run it BEFORE triggering the apply and save the output as the baseline
(`.../qr-resolver-baseline.txt` under the scratchpad, not the repo). A comparison
against an assumed baseline is not evidence — capture the real one.

Make the script re-runnable and idempotent; it performs GETs against a public redirect
service and has no side effects beyond a handful of scan log lines.
