<objective>
Make run.human mint short, single-use award links for BOTH ricky (by challenge name)
and all 8 persona ghosts (by fleet id), kill the full-table scan on the persona path,
and stop needing a raw flag code to exist for the challenge path.

Three locked decisions drive this:
- Mint-by-challenge resolves via `getCtf()` — a single GetItem. It MUST NOT use
  `listCtf()`, which is `Ctf.scan.go({pages:"all"})`.
- The persona answerHash-match fallback SURVIVES. Persona challenge names do not
  uniformly derive from fleet ids (`grace-hopper` <-> `ghost.hopper`). That mismatch is
  the entire reason the scan exists — do not "simplify" it away.
- TTL becomes 3600s via `BOT_CLAIM_LINK_TTL_SECONDS`, applied to ricky AND all 8 personas.

Purpose: the mint seam is where "genuinely single-use" is actually enforced, and where
the per-reveal table scan currently lives.
Output: a short-nonce generator, a `flagHash` park option, a two-shape mint endpoint,
and claim-page case tolerance.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| meshtk ghosts container -> POST /api/internal/ctf/mint | Server-to-server, authenticated only by the shared `AUTH_INTERNAL_SECRET` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-72-07 | Spoofing | `mint/route.ts` secret gate | high | accept | One shared internal secret can mint any flag. Raised in design, explicitly DEFERRED by the owner to a follow-up todo (per-bot scoping). Gate stays first-in-handler so an unauthenticated call touches no data |
| T-72-08 | Information disclosure | minted nonce / derived code | high | mitigate | No logging anywhere in the mint route or claim page; the challenge path parks the row's own `answerHash` so no raw code is constructed at all |
| T-72-09 | Elevation of privilege | forwarded award link | high | mitigate | `claimPending` deletes the pending row on first claim; `judgeSolve` conditional-put on `CtfSolve` backstops a lost delete so a re-claim echoes the prior award and never re-scores |
| T-72-10 | Denial of service | `listCtf` full-table scan per reveal | medium | mitigate | Challenge path and explicit-challenge ghost path both use `getCtf` GetItem; asserted by a never-called test on the scan |
| T-72-11 | Tampering | brute-forcing a 60-bit nonce | medium | mitigate | 12 Crockford symbols = 60 bits, single-use, dead in 3600s; an unbiased mask-based generator over `crypto.getRandomValues` avoids modulo skew |
| T-72-12 | Repudiation | award attribution | medium | mitigate | Credit is keyed to `session.user.id` (the Auth.js adapter uuid, the `RunUser.userId` key space) only — never the OIDC sub, never an id from query or cookie. Unchanged by this plan and must stay so |
