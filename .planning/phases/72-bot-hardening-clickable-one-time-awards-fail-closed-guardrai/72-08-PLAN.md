<objective>
Rotate ricky's static flag code dead and seed the mint-failure fallback secret.

Today `defcon.run/qr/rick_astley_loves_desert_running` serves a 474-byte static
interstitial whose HTML contains a fixed claim code in plaintext, three times, to anyone
who has ever loaded the page. That code is static forever and freely shareable — anyone
who saw it can claim 100 points daily, indefinitely. This plan kills it.

Blast radius is ZERO: pre-flight confirmed the row has `solveCount: 0`, so nobody has
ever claimed it.

⚠️ THIS PLAN MUTATES PRODUCTION DATA. It is DRY-RUN by default with a blocking human
review gate before any write. It performs only the non-destructive half of the rotation —
rewriting the answer hash. The DESTRUCTIVE teardown (deleting the Qr row and the S3
interstitial) is deliberately deferred to 72-10, AFTER the new award path is deployed and
verified, so there is never a window where the old path is dead and the new one is not
live.

Purpose: make "one-time" actually true.
Output: an operator rotation script and a populated fallback secret.
</objective>

Guard the whole thing on the region and profile being the intended production ones, and
print the resolved table name and region before doing anything, so a misdirected run is
obvious in the DRY-RUN output.

Do not add this script to any automated test run — it talks to production DynamoDB.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator workstation -> production DynamoDB | A destructive, irreversible write to live CTF scoring data |
| printed claim URL -> operator -> SOPS -> SSM -> ECS | A live flag code transits a human-mediated path with many leak surfaces |
| tracked git repository | Anything committed here is permanent and reviewable by anyone with repo access |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-72-40 | Tampering | resetting the ordinal allocator | high | mitigate | Conditional UpdateItem naming only the hash and timestamp, so unnamed attributes cannot be touched; pre/post read-back printed as evidence |
| T-72-41 | Tampering | script creating a row instead of updating one | high | mitigate | Condition expression requires the item to exist; a missing row exits non-zero instead of falling back to a create |
| T-72-42 | Information disclosure | new code leaking into git, logs or transcripts | critical | mitigate | Printed exactly once under `--confirm`; DRY-RUN prints no URL; stored only in encrypted SOPS; diff grepped for the code prefix and claim-query shape |
| T-72-43 | Information disclosure | echoing the SecureString value during verification | high | mitigate | Verification reads only parameter type and version, never the value |
| T-72-44 | Denial of service | ECS refusing to start on a missing parameter | high | mitigate | Secrets apply is sequenced strictly before the ecs-task apply in 72-09, and the parameter's existence is asserted here |
| T-72-45 | Elevation of privilege | premature teardown creating a dead-link window | medium | mitigate | Teardown is a separate, separately-flagged stage deferred to 72-10, after the new award path is deployed and verified |
| T-72-46 | Repudiation | writing against the wrong table or region | medium | mitigate | Resolved table and region printed before any action; region is a required env var with no default |
</threat_model>
