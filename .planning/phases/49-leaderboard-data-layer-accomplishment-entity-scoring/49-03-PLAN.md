<objective>
Port the DC33 `Accomplishment` entity into run.human as
`entities/accomplishment.ts` on the shared `run-human-electro` table, adapted to
the DC34 `electroClient`/`ELECTRO_TABLE` and identity model. Provide
`createAccomplishment` (writes the row AND atomically bumps the RunUser rollup via
49-01's `updateRunUserActivityCounts`), `getAccomplishmentsByUser`,
`deleteAccomplishment`, and an idempotency guard. Implements LDBR-01 and the
write-side half of the LDBR-12 CTF boundary (source enum excludes ctf/qr).

Purpose: this entity is the leaderboard's source of truth for the runs this board
owns (check-ins + GPX; Strava reserved). Ship the write path now, even with no UI,
so score data accrues quietly and is pre-populated when the hidden page is revealed.
Output: `accomplishment.ts` + a pure-helper unit test.

- `Accomplishment` ElectroDB entity: attrs `userId, accomplishmentId, type, source,
  name, description, completedAt, year, isPrivate, metadata{points, polyline, distance,
  elevation, gpxFileId, checkInId, stravaActivityId}, createdAt, updatedAt`; indexes
  `primary` (pk=userId, sk=accomplishmentId), `byType` (gsi1, pk=[userId,type], sk=completedAt),
  `byYear` (gsi2, pk=[userId,year], sk=completedAt).
- `type AccomplishmentItem`.
- `createAccomplishment(input)`, `getAccomplishmentsByUser(userId)`, `deleteAccomplishment(userId, accomplishmentId)`.
- Pure helpers: `accomplishmentIdFor(source, externalId)` (deterministic id) and
  `findDuplicate(existing, source, externalId)` (dup-guard predicate).
- `accomplishment.test.ts`.

<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| accomplishment source enum | The only place a run "type of origin" is set; must exclude CTF so CTF never becomes an accomplishment (spec §11) |
| create/delete → RunUser rollup | The sole path that moves activityScore; double-fire or drop causes score drift |

## STRIDE Threat Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-49-05 | Tampering | double-scoring via replayed create | high | mitigate | Deterministic accomplishmentId (sk collision) + `findDuplicate` guard; rollup bumped only on a genuinely new row |
| T-49-06 | Tampering | CTF written into Accomplishment | medium | mitigate | `source` enum is `["checkin","gpx","strava"]` only — ctf/qr are non-values; grep-gated (LDBR-12) |
| T-49-07 | Tampering | rollup drift on delete of a missing/foreign row | medium | mitigate | delete gets the row first, decrements only when it existed, floors at 0 (49-01) |
</threat_model>
