<objective>
Create the pure, unit-tested scoring module `lib/leaderboard-scoring.ts`: the point
constants, the read-time `globalScore = activityScore + (ctfScore ?? 0)`, and the DC33
rank comparator. This is the single source of truth for how the leaderboard (Phase 51)
ranks runners. Implements LDBR-03 and the read half of the LDBR-12 CTF boundary.

Purpose: scoring is the highest-leverage correctness surface and is trivially pure, so
it gets its own fully-tested module (mirrors `admin-report.ts`). It reads the CTF judge's
`ctfScore`/`ctfSolves` off the same row it already has — no query, no coupling, `0` until
CTF ships — and NEVER writes CTF anywhere.
Output: `leaderboard-scoring.ts` + `leaderboard-scoring.test.ts`.

## Artifacts this plan produces
- `POINTS = { checkin: 1, gpx: 1, strava: 1 }` (tunable constants; no `ctf` key).
- `type ScorableUser` — the narrow read shape: `{ activityScore?, activityCounts?,
  latestActivityAt?, createdAt?, ctfScore?, ctfSolves? }`.
- `globalScore(u: ScorableUser): number`.
- `totalCount(u: ScorableUser): number` — `activityCounts.checkin + activityCounts.gpx + (ctfSolves ?? 0)`.
- `rankComparator(a, b): number` — the DC33 sort order.
- `leaderboard-scoring.test.ts`.
</objective>
