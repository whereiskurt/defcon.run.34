<objective>
Extend the existing `RunUser` ElectroDB entity with the denormalized leaderboard
rollup fields this board owns — `activityScore`, `activityCounts{checkin,gpx}`,
`latestActivityAt` — and add the single atomic mutator `updateRunUserActivityCounts`
that keeps them drift-free. This is the substrate the Accomplishment entity
(Plan 49-03) bumps and the leaderboard scan (Phase 51) reads. Implements LDBR-02.

Purpose: the whole v2.2 leaderboard is a cheap `scanAllRunUsers()` sorted by a
denormalized score — never an accomplishment-wide scan. That only holds if these
rollups are authoritative and only ever move via create/delete accomplishment.
Output: an additively-extended `run-user.ts` + a pure-helper unit test.

## Artifacts this plan produces
- `run-user.ts` attributes: `activityScore` (number, default 0), `activityCounts`
  (map `{checkin, gpx}`, defaults 0), `latestActivityAt` (number, optional).
- `RunUserItem` type gains the three optional fields.
- `updateRunUserActivityCounts(userId, { source, pointsDelta, completedAt })`.
- Pure helper `activityDelta(source, pointsDelta, increment)` (exported, unit-tested).
- `run-user-activity.test.ts`.
