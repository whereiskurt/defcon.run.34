<objective>
Build the server-side copy resolver for run.bib: `loadCopy(locale)` fetches the `ui-string` catalog once through the Next.js Data Cache and returns a single already-merged map, with a cached fallback chain (Strapi -> S3 export -> committed snapshot -> dev-only key). Ships the committed `copy-snapshot.json` offline floor and its `copy:snapshot` regeneration script, plus the env wiring that introduces the CMS read into run.bib for the first time.

Purpose: This is the core mechanism the whole milestone depends on — a fast, fallback-safe, never-throwing copy resolver whose fallback is as cheap as the happy path. Per D-01 the toolkit ships as a per-app file (`lib/copy.ts`), NOT a shared `packages/copy/` workspace; per D-02 its first home is `run.bib` (`apps/run.bib/webapp/src`) so Phase 37 exercises it immediately. Plan 03 carries its output to the client; Phase 37 is its first real consumer.
Output: `lib/copy.ts`, `lib/copy-snapshot.json`, `scripts/copy-snapshot.mjs`, `package.json` script, `.env.example` entries, and a vitest spec.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| run.bib server -> Strapi worker | Server reads catalog with the read-only Bearer token (server-only secret) |
| run.bib server -> CloudFront S3 export | Server reads public static copy.json fallback (not secret) |
| server -> client (Plan 03) | Only the resolved copy MAP crosses; token and CMS URL never do |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-36-01 | Information disclosure | STRAPI_API_TOKEN / CMS_INTERNAL_URL in copy.ts | high | mitigate | copy.ts is server-only (`import 'server-only'`); token read only server-side; never NEXT_PUBLIC_*; Plan 03 passes only the resolved map to the client |
| T-36-02 | Denial of service | Slow/hung Strapi read on every render | high | mitigate | ~2.5s AbortSignal.timeout on the Strapi fetch; unstable_cache caches the resolved map so at most one slow call per revalidate window; stale-while-revalidate serves the last good map |
| T-36-03 | Denial of service | CMS + S3 both unreachable at cold start | medium | mitigate | committed copy-snapshot.json is a zero-network static import floor; resolveCopy never throws |
| T-36-04 | Tampering | Malicious/garbage copy.json from S3 path | low | accept | copy is not secret; values are escaped+whitelisted at render (Plan 02) before display; JSON.parse failure is caught and falls through to snapshot |
| T-36-SC | Tampering | npm/pip/cargo installs | low | accept | No new packages introduced this plan (D-05: no new deps); snapshot script uses global fetch; no legitimacy gate required |
</threat_model>
