<objective>
Add a run.flash "Sync keys" action for a re-flashed / re-keyed device: connect over Web Serial, read back the device's real on-device X25519 keypair from SECURITY_CONFIG, and register it via the existing `POST /api/register-radio` — with NO full re-provision (no flash, no config push, no region write). This is the human-side fix for the incident's staleness mode: a reflash regenerates keys, and Sync keys pushes the new pubkey to the DDB-authoritative store within one keycache TTL.

Purpose: Success Criterion #3's re-key path ("reflash → Sync keys → meshtk decrypts against the new key").
Output: `syncKeys()` in use-configure.ts + a Sync keys button in the Done step.
</objective>
