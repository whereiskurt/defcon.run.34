<objective>
Wire the `keycache` (plan 66-06) into meshtk's decrypt path: replace both `FetchPublicKeyFromDefcon` (nodes.json) call sites with `keycache.Resolve`, behind a `fallback` flag. `fallback=nodes.json` (the code default, for bring-up) falls back to the feed on a miss; `fallback=none` (the deploy-time target) returns an error so the existing `nackHandler` fires — closing pubkey poisoning. Add the parallel `KeyCacheConfig` and thread one shared resolver into the `MqttClient`. Every fallback/miss is logged so enrollment coverage can be measured before flipping to `none` at deploy time.

**Repo:** `~/working/meshtk` (same feature branch as plan 66-06, its own PR). Do NOT touch `apps/run.mqtt/meshtk` in the monorepo.

Purpose: This is the decrypt firewall — Success Criteria #1 (DDB key decrypts a real DM) and #3 (bogus injected key ignored under fallback=none).
Output: config + both call-site swaps + fallback branching + logging + a security-regression test. The `fallback=none` flip itself is a deploy-time op, out of scope; the flag and the `none` code path ARE implemented and unit-tested.
</objective>
