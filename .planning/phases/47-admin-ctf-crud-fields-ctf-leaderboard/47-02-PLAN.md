  <behavior>
    - planCtfMigration({ challenge, answer:"secret" }) with no answerHash → { action:"hash-and-clear", answerHash: hashAnswer("secret") }.
    - planCtfMigration({ challenge, answer:"secret", answerHash:"<existing>" }) → { action:"clear-only" } (answerHash already set; only strip plaintext).
    - planCtfMigration({ challenge, answerHash:"<existing>" }) (no plaintext) → { action:"skip" }.
    - planCtfMigration({ challenge }) (nothing) → { action:"skip" }.
    - planCtfMigration({ challenge, answer:"   " }) (whitespace-only) → { action:"skip" } (nothing meaningful to hash).
    - Applying the plan twice is a no-op: after hash-and-clear, the row has no plaintext answer, so a re-plan returns skip.
  </behavior>
  <action>
    Create `src/lib/ctf-migration.ts` exporting a pure `planCtfMigration(row: { challenge: string; answer?: string; answerHash?: string })` returning a discriminated result `{ action: "skip" } | { action: "clear-only" } | { action: "hash-and-clear"; answerHash: string }`. Import `hashAnswer` from `./ctf-hash` (do NOT re-implement the salt/normalize — parity with the judge is load-bearing). Logic: treat `answer` as "present" only when it is a non-empty trimmed string; if not present → `skip`; if present and `answerHash` already set → `clear-only`; if present and no `answerHash` → `hash-and-clear` with `answerHash: hashAnswer(answer)`.
