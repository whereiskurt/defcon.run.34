<objective>
Extend the existing `/admin/qr` CTF CRUD (form + server validation layer) with the Phase-44 scoring fields and switch answer entry to hash-on-save, per CTF-10. The admin form gains `pointMax`, `pointFloor`, `maxSolves`, `firstBloodBonus`, and a `timeTiers[]` editor (reusing the QR datetime-local + preset-chip pattern). The server `ctfAttributes`/`upsertCtf` in `qr-admin.ts` hashes the answer with the existing `hashAnswer` seam and stops persisting plaintext `answer`, and — critically — leaves an existing `answerHash` intact when the admin edits a challenge without re-entering the answer.

Purpose: make the greenfield CTF judge operable by admins with the real scoring curve, and eliminate plaintext answer persistence at the write boundary.
Output: extended `qr-admin.ts` write layer, extended `CtfForm.tsx`, and vitest coverage of hash-on-save + no-clobber + timeTier validation.
</objective>
