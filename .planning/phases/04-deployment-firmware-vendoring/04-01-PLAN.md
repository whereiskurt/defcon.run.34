**Create `apps/run.flash/webapp/Dockerfile.webapp`** -- a 3-stage multi-stage Docker build:

**Stage 1: firmware** (FROM node:current-alpine AS firmware)
- Install curl and unzip (apk add --no-cache curl unzip)
- WORKDIR /firmware
- ARG FIRMWARE_VERSION="" (optional override for testing new versions)
- COPY src/config/firmware.ts /tmp/firmware.ts
- If FIRMWARE_VERSION not provided, extract it from firmware.ts using: grep 'FIRMWARE_VERSION' /tmp/firmware.ts | head -1 | sed 's/.*"\(.*\)".*/\1/'
- Download all 4 ESP32 architecture zips from GitHub releases (esp32, esp32s3, esp32c3, esp32c6)
  - URL pattern: https://github.com/meshtastic/firmware/releases/download/v${FW_VER}/firmware-${ARCH}-${FW_VER}.zip
  - Use `curl -fL` with `|| { echo "Warning: ${ZIP} not found"; continue; }` for graceful failure
  - Extract only firmware-*.bin files with `unzip -q -o`
  - Delete -update.bin variants (we only want factory images)
  - Clean up zip files after extraction
- Log count of extracted binaries

**Stage 2: builder** (FROM node:current-alpine AS builder)
- Install build dependencies: curl, build-base, g++, libpng, libpng-dev, jpeg-dev, pango-dev, cairo-dev, giflib-dev, python3 (same as run.human)
- WORKDIR /app
- COPY package*.json and npm install
- COPY . . (entire webapp source)
- COPY --from=firmware /firmware/ ./public/firmware/ (firmware binaries land in public/firmware/ for build.sh extraction)
- Accept build args: NEXT_PUBLIC_ASSET_PREFIX, WEBAPP_PREFIX, WEBAPP_ORIGIN (default "flash.defcon.run"), VERSION_NGINX, VERSION_WEBAPP, REGION_SHORT
- Set ENV from build args (same pattern as run.human Dockerfile)
- RUN npm run build

**Stage 3: runner** (FROM node:current-alpine AS runner)
- WORKDIR /app
- Install curl for health checks (apk add --no-cache curl)
- COPY --from=builder /app/.next/standalone ./
- COPY --from=builder /app/.next/static ./.next/static
- COPY --from=builder /app/public ./public (this includes firmware binaries for build.sh S3 extraction)
- USER node
- EXPOSE 3000
- CMD ["node", "server.js"]

**Update `apps/run.flash/webapp/src/config/firmware.ts`** -- change FIRMWARE_BASE_PATH for production S3 serving:

Replace the existing line:
```typescript
export const FIRMWARE_BASE_PATH = "/firmware";
```
With:
```typescript
/** Base path for firmware binaries.
 * In production, firmware is served from S3 via CloudFront using the asset prefix.
 * In development, served locally from public/firmware/.
 */
export const FIRMWARE_BASE_PATH = process.env.NEXT_PUBLIC_ASSET_PREFIX
  ? `${process.env.NEXT_PUBLIC_ASSET_PREFIX}/firmware`
  : "/firmware";
```

Note: NEXT_PUBLIC_ASSET_PREFIX is set at build time by build.sh to `/${WEBAPP_PREFIX}/public` (e.g., `/use1/assets/public`). So production firmware path becomes `/use1/assets/public/firmware/filename.bin`. This path is served by CloudFront from S3. The `loadFirmware()` function already uses `${FIRMWARE_BASE_PATH}/${filename}` which will resolve correctly.

IMPORTANT: FIRMWARE_BASE_PATH must be a build-time constant (not runtime) because NEXT_PUBLIC_ env vars are inlined at build time. This is correct -- the value is frozen per region build, which matches the S3 asset path.
