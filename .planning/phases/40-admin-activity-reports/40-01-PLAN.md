## Event line contract (LOCKED — shared with 40-02, 40-03, 40-04)

logEvent emits exactly ONE line to stdout per call, produced by a single `JSON.stringify`
(no pretty-print, no newlines inside). Field keys are the contract with the metric filters:

- `evt` — the event name string (e.g. `auth.signup`)
- `userId` — the app's user id (omit if unknown)
- `email` — the user's email (omit if unknown)
- `ip` — the FIRST hop of the `x-forwarded-for` header (`split(",")[0].trim()`); the real client IP
- `ua` — the `user-agent` header
- `meta` — an object for event-specific fields (may be empty)

Rules: wrap the entire body in try/catch and swallow; return `void`; never `await`-block the
request path; emit no PII beyond `userId`+`email` (these are the operator's own admin logs).

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-40-01 | Tampering | logEvent JSON line | medium | mitigate | Single JSON.stringify prevents field-injection creating a fake `evt`; metric filters match structured `$.evt` only |
| T-40-02 | Spoofing | x-forwarded-for ip | low | accept | First-hop ip is attacker-spoofable; documented as best-effort attribution, not an auth control |
| T-40-03 | Denial of Service | logEvent in request path | high | mitigate | try/catch swallow + no blocking await ensures logging can never break the sign-in path |
</threat_model>
