## Grounding corrections this plan encodes

1. **There is no `summary_polyline` to decode on the DC34 side.** ROADMAP HEAT-02 says the
   sources are "GpxFile S3 tracks + accomplishment/Strava `summary_polyline`s". In THIS
   repo that is one source, not two: `lib/strava-sync.ts:108-208` (`buildGpx` +
   `PutObjectCommand` + a `GpxFile` row with `source:"strava"` and a `conDay`) materialises
   every Strava import as a real GPX object in S3 at import time. `GpxFile` has no
   polyline attribute at all (`entities/gpx-file.ts:27-185`). So the DC34 builder reads
   GPX from S3 for every run, full stop — and `lib/polyline-decode.ts` is used ONLY by the
   DC33 backfill (71-04). This also dissolves CONTEXT's "dedup when a run has both a GPX
   track and a Strava polyline": one `GpxFile` row is one run is one track.

2. **The artifact key is under `uploads/`.** See 71-01's grounding section — the run-gpx
   S3 IAM user is prefix-scoped. Always go through `heatmapArtifactKey()`.
