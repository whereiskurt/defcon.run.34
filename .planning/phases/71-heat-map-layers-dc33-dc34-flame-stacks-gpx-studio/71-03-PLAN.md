## The `?meta=1` addition and why it exists

CONTEXT D-10 locks "default OFF, fetch artifact on first enable", and ROADMAP success
criterion 4 says the layers must "cost nothing until toggled". CONTEXT D-11 simultaneously
requires a "last calculated" stamp visible on the section before anything is toggled, and
the Phase 70 dialog convention is that an unavailable section stays hidden entirely
(`LayerControl.svelte:511-522`). Those two are only compatible if availability + stamp can
be learned cheaply.

So the route accepts `?meta=1` and answers with the `meta` block alone — a few hundred
bytes, same cache headers, same CDN entry rules (each distinct query value is its own
cache entry, exactly as `public/checkins/route.ts` already relies on). The studio calls
`?meta=1` for both years at map load and fetches full geometry only on first enable. This
is an addition to the CONTEXT-locked API shape, not a change: `/api/gpx/public/heatmap/{dc33|dc34}`
still returns the whole artifact.

## STRIDE Threat Register

ASVS L1; block on `high`.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-71-10 | Tampering | `[year]` dynamic segment → S3 key | high | mitigate | `isHeatmapYear()` allowlist runs before `heatmapArtifactKey()`; the raw segment is never interpolated into a key, a URL, or a log line. Enforced by a source-ordering acceptance criterion and a `dc32 → 404` smoke check |
| T-71-11 | Denial of service | unauthenticated public route | high | mitigate | Response size is bounded upstream (`MAX_RUNS` 5000 × `MAX_TRACK_POINTS` 300 × 5-dp coordinates); the route does no per-request computation beyond one S3 GET and a parse; `s-maxage=900` means CloudFront absorbs repeat traffic. The site's WAF posture is unchanged from every other public gpx route |
| T-71-12 | Information disclosure | error responses | medium | mitigate | Every failure path returns a fixed generic message; the S3 error, bucket name and key are logged server-side only. Missing artifact returns 404 rather than an oracle-ish 500 |
| T-71-13 | Information disclosure | cache poisoning / private data in a shared cache | high | mitigate | The route reads no cookie and calls no `auth()`, so there is no per-user variation that a shared CDN entry could leak. `?meta=1` is a distinct cache entry, matching the existing `checkins` route's per-value convention |
| T-71-14 | Repudiation | superseded compliance comment | medium | mitigate | HEAT-06 Task 3 records the decision, its date, its owner, and the compensating control in the code itself, so the widened publication is auditable from the source rather than from planning artifacts alone |
| T-71-SC | Tampering | npm/pip/cargo installs | high | mitigate | No packages installed in this plan; `git diff --stat apps/run.gpx/webapp/package.json` empty |
