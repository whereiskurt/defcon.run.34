## Ship-path constraints (AGENTS.md — non-negotiable)

- **Deploy only via GitHub Actions.** Local tooling builds and pushes images to ECR; the
  `deploy.yml` workflow merges the Release PR, applies ECS via Terragrunt, and invalidates
  CloudFront. Never `terragrunt apply` locally, never `release-all.sh --with-terragrunt`.
- **The scheduler's Terraform applies through `terragrunt-apply.yml`** scoped to
  `region=us-east-1, modules=heatmap-scheduler` — `deploy.yml` only handles `ecs-task` /
  `ecs-service`, so the new unit will NOT ride along with the app deploy.
- **Branch + PR, no auto-merge.** Work on a feature branch; open a PR; do not merge without
  explicit approval.
- **`env.local.sh` worktree landmine.** It is gitignored and absent from a fresh worktree.
  `build.sh` reads `TF_VAR_profile_prefix` from it to form the `dc34-application` profile;
  without it the profile collapses to a bare `application`, and the run dies at the
  post-build S3 static-asset sync with exit 255 *after* the images already pushed. Copy it
  from the main checkout into this worktree root before releasing.
- **Immutable ECR.** The Release PR's VERSION bump must produce a NEW tag; never
  `--skip-bump` onto an already-released version. Current version is `v0.0.108`.
- **CI green is not proof.** ECS does a rolling replace, so verify the live version actually
  rolled before running the post-deploy probe.
