## Grounding corrections this plan encodes

These override a naive reading of CONTEXT.md / ROADMAP.md. They were verified against the
live codebase and live AWS during planning; do not re-derive them.

1. **The artifact key lives under `uploads/`, not at the bucket root.**
   `infra/terraform/live/site/services/run.gpx/service.hcl:279` sets
   `full_bucket_access = false`, and `infra/terraform/modules/s3-uploads/v1.0.0/iam.tf`
   scopes every PutObject/GetObject statement to `${bucket}/uploads/*`. The webapp's
   `s3Client` authenticates as exactly that IAM user. A key like `heatmap/dc34.json`
   would AccessDeny at runtime. Key is therefore `uploads/HEATMAP/{year}.json`,
   following the existing reserved-sentinel convention (`uploads/ROUTES/{routeId}.gpx`
   in `lib/s3-client.ts:45`, and `GLOBAL` as a reserved userId).
   The gpx bucket has NO ObjectCreated notification wired (`site.hcl:263-269`
   `upload_processors.processors` lists only `run_human`), so writing under `uploads/`
   triggers nothing.

2. **No npm dependency is added for polyline decoding.** PATTERNS.md correctly reports
   that no decoder exists in this repo. The decision here is to port ~25 lines of the
   Google encoded-polyline algorithm rather than add `@mapbox/polyline`: run.gpx/webapp
   has 12 runtime dependencies and this decoder is used by exactly one frozen one-off
   backfill. See `<threat_model>` T-71-SC.

3. **`meta` is EMBEDDED in the artifact, not a sidecar** (Claude's Discretion in
   CONTEXT.md). One object, one fetch, one atomic write — a sidecar can skew against its
   artifact and doubles the request count on a CDN-cached public path. GeoJSON permits
   foreign members on a FeatureCollection and Mapbox ignores them.
