<objective>
Close the two infrastructure gaps that the verifier proved by hand and that the shipped
probe could not see.

**CR-03:** three back-to-back identical requests to the public heat-map route all returned
a cloudfront miss, because the catch-all region behaviour uses the managed caching-disabled
policy and therefore ignores the origin's s-maxage. Every anonymous hit is one S3
GetObject plus a 441 KB body off a single ECS task, and the route's size bounds were
reasoned about on the premise that the CDN absorbed repeat load.

**CR-01 (network half):** a raw POST from the open internet to the internal build route
returns the application handler's own body, so the request traverses CloudFront and the ALB
and reaches Next.js. The documented network layer does not exist.

Both are the same one-file fix, and both are availability exposures during con week, so
they ship together on one scoped apply.

Purpose: this is the plan with real blast radius — the CloudFront module is shared by
fifteen distributions and the ALB rule it fronts serves other apps. The plan is built
around proving the change is confined, not around asserting it.

Output: two gpx-scoped ordered behaviours ahead of the region wildcard, two new global
resources, one changed distribution, and a CI plan output that proves the count.
</objective>

a response object with a 404 status, the matching status description, and a response header

production probe distinguish an edge refusal from the application's own rejection — the
predicate that previously could not tell them apart is what let CR-01 ship — and that
removing the header silently blinds probe assertions 8 and 15.

`aws_cloudfront_cache_policy "heatmap_artifact"`, named by sanitising the zone name's dots

TTL 900 (agreeing with the route's own `CACHE_SECONDS`), max TTL 3600. Enable gzip and
brotli accept-encoding in the cache key — the artifact is JSON and compresses heavily.
Cookie behaviour none, header behaviour none, query-string behaviour whitelist with exactly
one item: `meta`.

Comment three things: that the managed caching-optimized policy is deliberately NOT used
because it ignores query strings entirely, which would collide the bare artifact and the
meta projection into one entry; that a header behaviour of none combined with the
all-viewer origin request policy means every viewer shares one entry, which is correct
BECAUSE the route performs no session lookup and no cookie read (that absence is the whole
of what makes it public); and that if a session read is ever added to that route this
policy must be revisited first.

(c) **The internal-path edge block, gpx only.** Immediately BEFORE the `/{region}/*` ALB
wildcard dynamic block, add two ordered behaviours:

caching-disabled policy, the same conditional impart/ALB target and the same conditional
