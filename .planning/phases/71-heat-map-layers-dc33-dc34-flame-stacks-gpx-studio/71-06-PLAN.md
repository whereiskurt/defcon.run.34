## Grounding corrections this plan encodes

1. **`Section.svelte` has no `trailing` prop.** CONTEXT D-11 says the "last calculated"
   stamp goes in the section's trailing slot. Verified against
   `dialog-shell/Section.svelte:8-32`: the props are `label`, `count`, `master`, `onmaster`,
   `collapsed`, `ontoggle`, `variant`, `collapsible`, `hint`, `menu`, `children`. `trailing`
   is a prop of `Row.svelte` (line 14), not `Section`. `count` is typed
   `number | string` and renders at `Section.svelte:78-80` in a muted mono span — which is
   exactly a stamp slot. So the relative stamp is passed as `count`. This is the
   lower-risk reading of the spec and needs no change to the shared kit.

2. **The hint bar is reached through `data-hint`, not an import.** `Section.svelte:40` and
   `Row.svelte:32-33` set `data-hint` from their `hint` prop; `HintBar` reads it. So
   "hint bar shows exact timestamp + run count on hover" means passing a composed `hint`
   string to the `Row`. Do not import `HintBar`.

3. **`showChevron` requires children.** `Section.svelte:34` derives
   `collapsible && !!children`; a Section with no children renders no chevron and its label
   button is disabled. Since this section always has rows when it renders at all, that is
   fine — but it is why the availability guard must live at the mount site, not inside.

4. **Deliberately NO visibility-drives-collapse effect.** `PublicOverlays.svelte:48-101`
   carries two `$effect` blocks with per-entry seeding sentinels, and its own comments
   explain the bug class they exist to avoid (a first sighting read as an ON transition
   rewrites the restored collapse state). This section does not adopt that behaviour at all:
   collapse here is manual-only. That sidesteps the entire bug class rather than
   re-implementing the guard against it. State the reasoning in a comment.

5. **Section placement is order-safe.** The Phase 70 production probe (assertion 5 in
   `.planning/phases/70-*/70-06-probes/dialog-shell-probe.cjs`) requires the first section
   to be Basemap and requires pairwise ordering among Basemap → User Check-ins → route
   groups → My DEF CON Runs → Community Routes. Inserting HEAT MAP between the
   `PublicOverlays` block and `MyConRuns` satisfies all of those. Do not place it first.
