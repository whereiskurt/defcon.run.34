## Decisions this plan locks (Claude's Discretion, from CONTEXT.md)

- **Paint (D-02):** `line-color` `#ff0000` for dc34 and `#ff8c00` for dc33; `line-width` 3;
  `line-opacity` 0.25; `line-join` and `line-cap` `round`. DC33's own renderer used
  `opacity 0.7 / weight 4`, but that was Leaflet drawing one polyline per activity; in
  Mapbox a single GeoJSON source of hundreds of overlapping LineStrings composites far more
  aggressively, and the shipped in-repo precedent for exactly this effect is
  `public-overlays.ts:538` at `opacity 0.15 / width 2`. 0.25 at width 3 sits between them:
  a lone run is visibly faint, a well-trodden path saturates.
- **Stacking order:** DC33 is added to the map FIRST so DC34 renders above it. The live year
  wins where they overlap, which is what "DC34 — live" means.
- **No test runner exists in `gpx-studio/website`** (`package.json` has `check`, `lint`,
  `build` and no `test`). Verification for this plan is therefore `svelte-check` + `build` +
  source assertions here, with behaviour proven by the production Playwright probe in 71-08.
  That is stated rather than papered over.

## Grounding corrections this plan encodes

- **Cheap availability probe.** `?meta=1` (added by 71-03) is fetched for both years at map
  load; it returns only the meta block. Geometry is fetched on first enable. This is what
  makes "default OFF, costs nothing until toggled" and "the section shows a last-calculated
  stamp before you touch anything" simultaneously true.
- **PATTERNS.md §6 is right that `public-overlays.ts` `addAggregate()` already ships this
  technique.** Treat it as the primary template for the data path and `deuce-layer.ts` for
  the class shape; do not invent a third idiom.
