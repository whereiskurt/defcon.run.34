## Connect/error UX (BRND-02)
Reference for alignment: flasher.meshtastic.org's current Connect step (developer knowledge — no runtime fetch). Focus areas:

1. **Bootloader-help** (`components/connect/bootloader-help.tsx`) — current copy is generic ESP32; keep the BOOT/RESET sequence (it's correct) but:
   - Tighten intro copy so the "when do I need this?" is obvious (a serial-connect failure).
   - Update the outbound link target to the current Meshtastic getting-started/flashing docs URL (verify the URL is still correct — as of Phase 18 it points to `meshtastic.org/docs/getting-started/flashing-firmware/`, which is the currently-shipping URL; leave in place if still valid).
   - Add one line noting that some devices auto-enter bootloader on connect (so the user doesn't manually press BOOT unnecessarily).

2. **Chip-mismatch** (`components/connect/chip-mismatch.tsx`) — current copy already says "Chip Mismatch Detected" and names detected vs. expected. Keep the block-flash behavior; tighten the copy so the corrective action is a single sentence ("Return to the device picker and select {expectedArchitecture} — or disconnect and connect the correct device").

3. **Serial errors** (`components/connect/connect-step.tsx`) — where the hook surfaces a serial-connect error, categorize the failure and show human copy per category rather than the raw exception. Minimum categories:
   - No Web Serial support (already gated at `browser-gate.tsx` — this shouldn't normally reach connect-step, but a defensive message is worth having).
   - User cancelled the browser serial prompt (not an error, no scary message).
   - Serial port already in use (Arduino IDE, PlatformIO, another tab) — copy points at BootloaderHelp #2.
   - No response from device (likely bad cable or device not in bootloader) — copy points at BootloaderHelp #3–5.
   - Generic esptool failure — copy points at BootloaderHelp accordion generally.

The developer should read `connect-step.tsx` to see the current error-handling shape; if there is no existing categorization, add a small helper (inline in the file — no new module) that maps a caught error to one of the categories above. Do NOT introduce an i18n system or a new error-message registry.
