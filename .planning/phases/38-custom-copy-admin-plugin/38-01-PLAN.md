<objective>
Add the server half of the Custom Copy Admin page: a single admin-authenticated `POST /ui-strings/bulk-upsert` endpoint on the existing `api::ui-string` that upserts a batch of dirty + new rows all-or-nothing, enforcing `(key, locale)` uniqueness (ADMN-03, D-02, D-03).

Purpose: Give the Phase 38-02 admin grid one bulk-save endpoint that reuses the Phase-35 write path — so an admin edit gets the same `(key,locale)` uniqueness guard and the same copy.json S3 export the default content-manager already gets, with no divergent duplicate logic.

Output: A custom bulk-upsert route + controller action + service helper on `api::ui-string`. No new schema, no migration, no new dependency (the `ui-string` type, its `(key,locale)` DB unique index, the lifecycle uniqueness guard, and the S3 export all shipped in Phase 35 and are reused as-is).

Scope note (schema-push gate evaluated): this plan creates NO ORM schema file and NO DB migration — it only adds a custom route/controller/service on an existing content-type — so no schema-push task applies.
</objective>

  <behavior>
    - Pure batch validation, no strapi: given rows, two rows sharing the same (key, locale) → both flagged as a duplicate-pair conflict, nothing writeable.
    - Pure batch validation: a row whose key does not start with a valid namespace prefix (key.split('.')[0] not in [common,human,auth,gpx,bib,flash]) → flagged bad-namespace-prefix.
    - Pure batch validation: a row missing key or value → flagged empty-required-field.
    - Pure batch validation: a valid, unique, well-namespaced batch → zero errors.
    - Row discrimination: a row carrying a DB id → treated as an in-place update (same key,locale is NOT a conflict); a row without an id → treated as a create.
    - Atomicity: if any row would collide against a DIFFERENT existing DB row, the whole batch is rejected and nothing is persisted (verified live in 38-03).
  </behavior>
  <action>
    Convert the bare factory service to the customizer form (createCoreService with the `({ strapi }) => ({ ... })` second argument, mirroring the controller/service customizer shown in 38-PATTERNS). Add an async `bulkUpsert(rows)` method returning `{ saved, errors }`.

    Implement the observable requirement — atomic all-or-nothing with per-row errors (D-03), reusing the Phase-35 uniqueness rule and S3 export, NOT re-implementing either:

    1. Pre-flight validation pass (keep this as a small pure local helper so it is independently testable and free of the `strapi` global). Over the submitted rows: (a) detect intra-batch duplicate `(key, locale)` pairs (default a missing locale to "default", matching lifecycles.ts); (b) derive the namespace from `key.split('.')[0]` and validate it against the enum from schema.json `[common, human, auth, gpx, bib, flash]` (D-05); (c) reject empty required `key` or `value`. Collect an error object per offending row keyed by its submitted index (`{ index, code, message }`). Use the exact user-facing wording from 38-UI-SPEC "Copywriting Contract" row-error rows so the grid renders the same strings.
    2. Cross-row uniqueness against existing DB rows: for each row that is a create (no id) OR an edit that changes `(key, locale)`, query for an existing row with the same `(key, locale)` on a DIFFERENT id (same shape as the lifecycles.ts beforeUpdate guard) and, if found, add a duplicate-pair error for that row's index. Running this pre-flight over the whole batch BEFORE any write is what guarantees the batch either fully succeeds or writes nothing — so the per-row S3 export never fires on a rejected save.
    3. If the pre-flight collected ANY error → return `{ saved: [], errors }` immediately, writing nothing.
    4. Otherwise write the batch: open one `strapi.db.transaction(...)` and, for each row, write through the entity/document service (the same path the default content-manager uses) so lifecycles.ts fires naturally — giving the `(key, locale)` guard as a backstop AND the copy.json S3 export (afterCreate/afterUpdate) for free. Rows with an id → update; rows without an id → create. Per-row export on master is acceptable per D-03; collapsing to a single `regenerateAndUpload` call is an optional optimization only if it does not bypass the uniqueness guard. If any per-row write still throws a ValidationError, roll the whole transaction back and return `{ saved: [], errors: [{ index, message }] }` — nothing persisted.
    5. On full success return `{ saved: [{ index, id, key, locale }, ...] }` so the controller/grid can reconcile new-row client keys with their DB ids.

    Do not touch the `(key,locale)` uniqueness logic in lifecycles.ts or the export in copy-export.ts — reuse both. Transaction strategy (validate-all-then-write vs pre-flight check) is Claude's Discretion per CONTEXT; the pre-flight-then-write path above is the recommended one because it keeps the S3 export off rejected batches.
  </action>

  </verify>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser → admin/content API | Authenticated Strapi admin (SSO-backed via src/admin/app.tsx) submits a bulk write batch. |
| read-only toolkit token → content API | The runtime copy toolkit's read-only API token can `find`/`findOne` but MUST NOT reach this write endpoint. |
| stored markdown `value` → downstream render | `value` is stored raw; it is rendered later by the Phase-36 escape-first sanitizing renderer, never as HTML by this endpoint. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-38-01 | Elevation/Spoofing | `POST /ui-strings/bulk-upsert` | high | mitigate | Route omits `config.auth:false`, so it stays behind admin/API-token auth (Task 2). The Phase-35 read-only token grant excludes create/update, so it cannot write here (verified in Phase 35's 403 matrix). |
| T-38-02 | Tampering | rows array input validation | medium | mitigate | Pre-flight validation rejects empty required `key`/`value` and a `key` whose `key.split('.')[0]` is not in the namespace enum; controller rejects a non-array body (Tasks 1–2). |
| T-38-03 | Tampering | silent duplicate overwrite | medium | mitigate | Atomic all-or-nothing: any intra-batch or cross-row `(key,locale)` collision rejects the whole batch and writes nothing, reusing the Phase-35 uniqueness guard (Task 1). No last-write-wins. |
