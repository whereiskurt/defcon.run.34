**What replaces the human gate.** Each merge is preceded by a hard MECHANICAL MERGE GATE
defined below. The gate is not advisory: if any item fails, the executor STOPS, names the failing
item, leaves the PR open and surfaces to the owner. It never merges past a red gate and never
"fixes" a gate by editing the thing being asserted. Upstream `whereiskurt/meshtk` main is code
production runs — `apps/build.sh resolve_meshtk` shallow-clones it on every release — so its gate
is as strict as the monorepo's.

The upstream repository has no CI, so the four local gates (`go build ./...`,
`go vet ./internal/app/server/`, `go test ./internal/app/server/`, and the env-gated
live-mosquitto e2e) ARE the entire gate. They must be run from the branch tip AND re-run from
the merged state, because "green before the merge" and "green after the merge" are different
claims.

Purpose: get the fixes into the tree the release actually builds from, without reintroducing
either of the two regressions this repo has already shipped twice — a stale-overlay sync that
reverts upstream work, and an overlay sync that clobbers the monorepo-authoritative GPX embed.
Output: an upstream merge commit, a byte-parity-verified monorepo overlay, and a merged
vendor-sync PR.

**Landmines this plan must actively avoid.**
1. The `release/2026-07-26-230957` checkout carries a stale v0.0.66 overlay with **no v5 files
   at all**. Reading or syncing from it produces a silent revert of meshtk#22/#23/#27. Work from
   `origin/main`.

   change without a matching `vendor/` update fails the image build with `inconsistent

   assert it rather than assume it.

   embeds only `example/*.gpx`. Overwriting it is exactly the #1009 regression that stranded all
   24 GPX-driven sim nodes, twice. Never sync it; prove it unchanged by hash.
4. `VERSION` is monorepo-only and buildpub owns the bump. Do not hand-edit it.
5. In this checkout the `main` branch is pinned by another worktree; `local-main-track` is the
   local tracking branch for `origin/main`. Branch from `origin/main` explicitly rather than
   assuming `main` is checked out or current.
6. A parity sweep over files that exist in BOTH repositories is blind to a file that was never
   copied at all. The reverse-direction check exists because six of this phase's new files are
   test files, and a skipped test-file sync would otherwise pass every forward assertion.
