<objective>
Give the CR-04 hand-parsed PUBLISH path the topic-alias guard its codec sibling already has
(MQFX-04 item a / `68-REVIEW.md` WR-01), and retire the test name that still advertises the
fail-open posture Phase 68 removed (MQFX-04 item e).

- **(a) WR-01** — the hand-parse PUBLISH path documents itself as mirroring its codec sibling
  "decision for decision" and does not: the sibling Blocks on `Properties.TopicAlias != nil`,
  the hand-parse path skips the property block whole and cannot see it. PROVEN: a PUBLISH
  carrying `TopicAlias=7` plus an unmodelled id was ALLOWED on the hand-parsed path.
- **(e)** — `TestV5PublishParseFailureForwardsRaw` still names the retired fail-open posture.

Purpose: remove the asymmetry that lets a client pick which inspection path judges it, without
reintroducing the defect class that asymmetry came from.
Output: an alias-aware hand parser that never gates inspection on a property table, a wired
guard with honest telemetry, and an honest test name.

SUBSCRIBE seam and the CONNACK branches in one plan — two new wire parsers, a fourth
`RawPacket` member, a third rule branch, a shared-switch extraction and three new test files.
That is over a single agent's context budget, and this phase pays serialization on every plan
anyway (one shared upstream working tree), so splitting costs nothing but plan count. The
SUBSCRIBE seam and the CONNECT failure branches are now 69-05.

**Execution location.** Upstream `/Users/khundeck/working/meshtk` only, on the phase branch
69-01 created. Never `apps/run.mqtt/meshtk`; never `internal/embedded/`.

**Scope fence.** WR-03 (both relay paths handing mosquitto frames the proxy knows are
malformed) is NOT in MQFX-04 and is NOT in scope. WR-06 through WR-13 (other than item e) are
out of scope, including the `gofmt` wart (WR-12).
