<objective>
Close the two shared-chain criticals that live in the same two functions: the nil-cipher
dereference that lets one authenticated plaintext text message kill the whole proxy process
(MQFX-01, guard layers 1 and 2), and the `Data` field loss that silently strips `reply_id`,
`emoji`, `dest`, `source`, `request_id` and `want_response` off every rewritten text message
on the live fleet (MQFX-02).

`RewritePayloadString`, they are codec-symmetric, and they pre-date Phase 68. They are
planned together because they are literally the same two functions — splitting them would
mean two plans editing the same two files.

Purpose: stop a remote whole-process kill and stop live user-visible mesh data loss
(2.8 tapbacks, threaded replies, delivery ACKs, DM routing fields) before DEF CON 34.
Output: a hardened rewrite path plus a regression suite that pins both behaviors, landed as
commits on a single upstream `~/working/meshtk` branch that plans 69-02 through 69-05 extend
and 69-06 opens as a PR.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated MQTT client → proxy uplink read loop | any credential holder can choose the portnum, the encryption state and every `Data` field of an uplink packet |
| one connection's goroutine → the proxy process | the proxy is a single process serving the whole fleet; an unrecovered panic on one connection drops every connected radio |
| proxy rewrite helpers → mosquitto backend socket | what the rules mutate only reaches the mesh through `setPublishPayload`; a rewrite that silently fails forwards the original bytes |
