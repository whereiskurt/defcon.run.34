<objective>
Close the Last-Will inspection bypass on both codecs (MQFX-03) and the log-injection hole that
makes the phase's own verification telemetry forgeable (MQFX-04 item d).

**MQFX-03.** `grep -n Will` across `inspect.go`, `inspect_v5.go` and `proxy.go` returns nothing
today, so neither codec has ever inspected a Will. A Will topic and payload are re-encoded into
the CONNECT and handed to mosquitto, which publishes them on disconnect — so the payload never
traverses `handleV5PublishUplink`, never reaches `inspectV5Publish`, never reaches
`PacketDecider.Decide`, and is never touched by `RewriteHopLimit`, `BlockInvalidEncryption` or
the payload censor. `68-REVIEW.md` CR-02 PROVED it: a Will `ServiceEnvelope` with
`HopLimit: 7 / HopStart: 9` reached the broker inside the CONNECT, uninspected and unclamped.
It is a client-chosen uninspected uplink on any topic, replayable by reconnect-and-drop, and it
defeats the exact RF flood-radius control `RewriteHopLimit`'s own comment says it exists for.

**MQFX-04 (d).** `client_id`, `username` and `auth_method` go straight off the wire into
`InspectorLogger` format strings, and production uses `SimpleFormatter` — plain
`fmt.Sprintf("%s %s\n", timestamp, message)`, no quoting. WR-05 PROVED one CONNECT producing
two log lines, which forges the `action=AUTH_REJECT` / `action=MQTT5_CONNECT` / `action=ALLOW`
telemetry Phase 68's verification and the committed `mqtt5_probe.py` both rely on.

These ship together because they touch the same two files (`inspect.go` and `inspect_v5.go`),
and because the Will strip needs a sanitized `will_topic` in its own log line.

Purpose: remove the amplification bypass and make the security log trustworthy.
Output: Wills cleared and logged on both codecs, a sanitizer applied at every
`InspectorLogger` client-string boundary, and tests that pin both.

**Execution location.** Upstream `/Users/khundeck/working/meshtk` only, on the phase branch.
Never `apps/run.mqtt/meshtk`; never `internal/embedded/`.

**Design decision — strip, do not inspect.** The ROADMAP allows either clearing the Will or
routing its payload through the decider. Clear it: Meshtastic firmware and mqttastic do not use
MQTT Wills, so nothing the fleet does is lost, and routing an uninspected payload through the
decider means building a second, quieter inspection path — which is the defect class this whole
phase exists to close. The log line makes any real Will user visible.

**Design decision — one action name, both codecs.** Emit `action=WILL_STRIPPED` with a
`protocol_version=` field rather than a v5-prefixed variant, so one production grep covers both
codecs while the codec stays distinguishable. 69-07 greps for this exact string.

**Design decision — sanitize without gratuitous quoting.** A blanket `strconv.Quote` would
change every ALLOW / AUTH_REJECT / MQTT5_CONNECT line's shape and break the greps Phase 68's
verification and `mqtt5_probe.py` depend on. The forgery vector is specifically the newline, so
the sanitizer strips control characters and truncates, and quotes ONLY when the value would
otherwise break the `key=value` grammar or was modified. Clean values pass through
byte-identically.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted MQTT client → proxy CONNECT inspector | the client chooses the Will flag, Will topic, Will QoS, Will retain and Will payload, all pre-authentication in wire terms |
| proxy → mosquitto CONNECT forward | whatever survives the CONNECT inspector is published by the BROKER on disconnect, so it can never be seen by the uplink inspection chain |
| client strings → InspectorLogger → log file → S3 → ops greps and mqtt5_probe.py correlation | `SimpleFormatter` does no quoting, so any client string is a candidate log-line forgery vector |
