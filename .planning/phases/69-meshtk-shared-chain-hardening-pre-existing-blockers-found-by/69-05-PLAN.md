<objective>
Close the last two `68-REVIEW.md` warnings that Phase 68's own fixes introduced (MQFX-04 items
b and c). Item a and item e shipped in 69-04; item d shipped in 69-03.

- **(b) WR-04** — a SUBSCRIBE the codec cannot parse is relayed without reaching
  `inspectV5Subscribe` or `PacketDecider`, re-opening codec-dependent inspection one layer up.
  The exemption is bought with the same three client-chosen bytes as CR-04, and the first
  topic Block rule anyone adds will silently not apply to those frames.
- **(c) WR-02** — an unparseable v5 CONNECT is dropped with NO CONNACK, so the client gets a
  silent TCP close and hot-retries. That is the exact failure mode Phase 68 existed to remove
  (0x84 retry-looping), reintroduced one layer down.

Purpose: make inspection independent of which parser succeeded, and stop answering a refusal
with silence.
Output: a property-agnostic SUBSCRIBE seam that reaches the decider, and version-correct
answers on every CONNECT failure branch.

**Why this is its own plan.** It was originally the back half of a three-task 69-04 that also
carried the alias scan — two new wire parsers, a fourth `RawPacket` member, a third rule
branch, a shared-switch extraction and three new test files in one context. The SUBSCRIBE seam
alone is the heaviest single unit of work in this phase. The phase serializes every plan anyway
(one shared upstream working tree), so the split costs nothing but plan count.

**Execution location.** Upstream `/Users/khundeck/working/meshtk` only, on the phase branch
69-01 created. Never `apps/run.mqtt/meshtk`; never `internal/embedded/`.

**Scope fence.** WR-03 (both relay paths handing mosquitto frames the proxy knows are
malformed, after which the broker kills the session) is NOT in MQFX-04 and is NOT in scope for
the codec-parse-fail-but-hand-parse-OK relay. Leave that relay as it is; the one place this
plan chooses fail-closed is a SUBSCRIBE whose own length prefixes contradict its bytes, which
is the same bar `MQTT5_PUBLISH_HEADER_FAIL` already applies.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted MQTT client → v5 frame switch | the client chooses which inspection path judges it by choosing property bytes the codec cannot read |
| hand-parsed view → PacketDecider | anything the hand parser fails to report is a control the rules cannot apply |
| proxy → v5 client answer channel | a client that gets no answer cannot distinguish refusal from a network fault and retries |
| new InspectorLogger lines → log file → S3 → ops greps and probe correlation | `SimpleFormatter` does no quoting, so any unsanitized client string on a NEW line reopens WR-05 |
