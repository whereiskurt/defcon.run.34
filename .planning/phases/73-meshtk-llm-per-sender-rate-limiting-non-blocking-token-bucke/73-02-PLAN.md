<objective>
Make sustained per-radio abuse visible to an operator, and make the ceiling tunable in
production without a code change.

73-01 emits a marker token on every rate-limit refusal. On its own that is a log line
nobody reads. This plan turns it into a counted metric and a threshold alarm on the SNS
tripwire topic Phase 40 already built and Phase 72 already reused, and wires the meshtk
env knob onto the ghosts container so con-week tuning is a one-line edit rather than a
rebuild.

⚠️ LOCKED FAILURE POSTURE (Kurt, 2026-08-01): the alarm NOTIFIES ONLY. Nothing here may
auto-disable model calls, scale the service, or silence the fleet. Dead ghosts mid-con are
a worse failure than a visible overage.

⚠️ ACCEPTED RESIDUAL RISK: this alarm counts REFUSALS, not dollars. Aggregate spend across
many distinct radios each sitting just under the per-sender bucket remains UNBOUNDED and
raises nothing. An AWS Budgets / CloudWatch `InvocationCount` backstop — the only option
that would have bounded it — was offered to Kurt on 2026-08-01 and declined. Do not add it.

Purpose: detection and operator control, without ever taking the fleet off the air.
Output: a metric filter, an alarm, a tunable threshold, and a tunable per-radio ceiling.

TERRAFORM AUTHORING ONLY. The apply runs in GitHub Actions (73-03). Never run
`terragrunt apply` locally — that is Essential Rule 4 in AGENTS.md.
</objective>
