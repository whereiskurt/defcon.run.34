<objective>
Put the first bound of any kind on Bedrock spend driven from a single mesh radio.

`llm.go` has no limiter. Every unlocked DM to a ghost becomes a paid `Converse` call
against `us.anthropic.claude-haiku-4-5-20251001-v1:0` at `llmMaxTokens` 2000. The only
throttle anywhere in the path is `requestDedupWindow` (30s), which collapses
BYTE-IDENTICAL repeats via `isRetransmit` — it exists to swallow Meshtastic's ~3x
retransmits, and varying a single character defeats it entirely. The Phase 72 lyric
semaphore caps LYRIC fan-out to protect RF airtime, sits on a different path, and is
NOT a rate limit.

This plan adds a non-blocking per-`(fleet, sender)` token bucket immediately in front of
`generateReply`, refuses an exhausted sender in words, and tokenises the refusal log line
so 73-02's alarm can see sustained abuse.

⚠️ ACCEPTED RESIDUAL RISK (recorded, not an oversight): this bounds ONE radio. Aggregate
spend across MANY distinct radios each sitting just under the bucket remains UNBOUNDED,
and nothing in this phase alarms on cost. A global fleet cap, a daily token/spend ceiling
with kill switch, and an AWS Budgets / CloudWatch `InvocationCount` backstop were each
offered to Kurt on 2026-08-01 and each explicitly declined. Do not add them back under
another name.

Purpose: turn an unbounded per-radio spend loop into a bounded one, without ever
silencing the fleet.
Output: a token bucket, an operator kill switch, an in-character refusal, and a marker
token for the alarm.
</objective>
