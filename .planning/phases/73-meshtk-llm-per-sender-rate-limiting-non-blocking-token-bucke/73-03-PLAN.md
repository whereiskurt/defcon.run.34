<objective>
Get the limiter onto the mesh, and prove it from live AWS state.

73-01 wrote the bucket and 73-02 wrote the alarm. Neither bounds a single dollar until the
ghosts container is actually running the new image with the new task definition. CI going
green is not proof: ECS does a rolling replace, so the old task drains while the new one
health-checks, and a workflow can succeed while the previous image is still serving.

This plan opens both PRs, stops at a human gate, and only then merges, releases, deploys
and probes.

⚠️ HUMAN GATE IS MANDATORY. AGENTS.md Essential Rule 2: wait for explicit user approval
before merging, and never auto-merge. Task 2 is a blocking checkpoint; Tasks 1 and 3 sit
on either side of it. Nothing before Task 2 may merge, release or deploy.

⚠️ ACCEPTED RESIDUAL RISK carried into production (Kurt, 2026-08-01): this ships a
PER-RADIO bound only. Aggregate spend across many distinct radios each sitting just under
the bucket stays UNBOUNDED, and no alarm in this phase watches cost. The probe below
deliberately does NOT claim spend is bounded — only that the per-radio limiter and its
refusal alarm are live.

Purpose: make the bound real.
Output: two merged PRs, a released and deployed run.mqtt, and a re-runnable probe.
