# Phase 57 — UI Design Contract

> Visual and interaction contract for the CTF form/QR polish. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a RESTYLE phase over already-shipped, correctly-structured components.** The contract locks colors / spacing / typography / states / copy for two surfaces. It changes **zero** logic, structure, fields, payloads, or behavior (see `57-CONTEXT.md` D1–D5). The seed script (`seed-ctf.mts`, Slice C) has **no UI** and is out of scope for this contract.

| **A** | Admin CTF form | `src/components/admin/CtfForm.tsx`, `src/components/admin/qr-ui.ts` (`cls` token layer) | **Theme-aware HeroUI.** Adopt the mockup's *treatment* (segment glow, two-line labels, stat-tile preview, framed QR, mono uppercase labels, tighter rhythm) but stay in HeroUI semantic tokens. The mockup's cyan-on-dark QR is a fake illustrative canvas — do not reproduce it. **Ship gate:** scannable in a real Google Authenticator / Authy install before merge.

## Spacing Scale

The project rhythm is Tailwind's built-in half-step scale (a 2px grid), not a strict 8-point grid. Because this is a **restyle that must sit inside the existing form rhythm**, the contract declares the actual scale in use rather than forcing a false 4-point grid.

| Token | Value | Usage |
|-------|-------|-------|
| 2xs | 4px (`gap-1`, `p-1`) | Icon gaps, tightest inline |
| xs | 6px (`gap-1.5`) | Segment row gap, chip gaps |
| sm | 8px (`gap-2`, `mt-2`) | Checkbox↔label, help-text offset |
| md | 10px (`gap-2.5`) | Grid gaps, action-row gaps |
| lg | 14px (`gap-3.5`, `mt-3.5`) | Intra-section blocks (Surface B: card padding) |
| xl | 16px (`p-4`, `gap-4`) | Card padding (Surface A), reveal-card inner gap |
| 2xl | 20px (`gap-5`, `py-2 → py-16`) | Root section gap; claim page vertical padding uses `py-16` (64px) |

**Radius:** Surface A cards `rounded-xl` (12px, unchanged — theme-consistent); controls/inputs/segments/tiles `rounded-lg` (8px). Surface B reveal card **14px** (mockup); nested tiles `rounded-lg`; progress-ring bar `rounded-full` (999px); chain callout `rounded-lg` (8px).

**Exceptions:**
- Surface B adopts the mockup's exact card metrics: **14px radius, ~18px padding, ~14px inter-block margin** (bespoke-dark is allowed to leave the HeroUI rhythm).
- QR quiet-zone card keeps `p-2` (8px) white padding + `min-h/min-w-[220px]` — do NOT reduce (quiet-zone is scannability-critical).
- Touch targets: primary/segment controls stay at existing `h-9` (36px). "＋ Add to Authenticator" (Surface B) renders full-width — comfortable tap target on mobile claim.

## Color

### Surface A — theme-aware 60/30/10 (HeroUI tokens)

| Role | Token (dark / light) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `background` `#0a0a0f` / `#fafafa` | Page behind the form |
| Secondary (30%) | `content1` `#111118` / `#ffffff` (cards) · `content2` `#1a1a24` / `#f5f5f5` (nested panels: reward box, window box, advanced body, stat-tile container) | Card + panel surfaces |
| Accent (10%) | `primary` `#00d4aa` / `#00a888` | See reserved-for list below |
| Amber (semantic) | `secondary`/`warning` `#f59e0b` / `#d97706` | Timed-drop window note callout ONLY (the mockup's amber window-note) |
| Destructive | `danger` `#ef4444` | Delete button (`cls.btnDanger`) + inline error banner ONLY |

**Surface A accent (`primary`) reserved for — explicit list (never "all interactive elements"):**
1. Active/selected segment (`cls.segmentActive`) — border + soft inner glow (`box-shadow: inset 0 0 0 1px` primary at ~35% + `bg-primary/[.09]`, translated to theme-aware `bg-primary/10`).
2. Primary CTA buttons (`cls.btnPrimary`): "Create challenge" / "Save changes", "DEF CON run hours" quick-set.
3. Live-scoring preview stat **values** (mono numerals).
4. Active toggle labels ("Reward on solve → OTP enrollment", "Restrict scoring to a time window" when checked).
5. Focus ring on inputs (`focus:border-primary`, existing).

Everything else (labels, help text, borders, idle segments, chips) stays neutral (`default`/`divider`/`foreground`). Accent must NOT leak onto idle controls or body copy.

### Surface B — bespoke-dark (self-contained, ignores viewer theme)

| Borders | `--line #262b33` (card), `--line2 #333a44` (ring track, dividers) | Structure |

## Accessibility

- **Theme-aware contrast (A):** verify AA on both light and dark — accent `primary` text on cards, `default-400`/`default-500` body, amber note.
- **Bespoke-dark contrast (B):** verify legibility of `--cyan` hero and `--mint` button on `--card`; verify the full-dark card is legible when mounted over a **light**-theme device (D1 risk).
- **Preserve (B):** `sr-only aria-live="polite"` code-roll announcement; QR `alt`/`aria-label`; `aria-hidden` on decorative code/label spans. Add an accessible name/value to the new progress bar (sr-only "New code in Ns" or `role="progressbar"` + `aria-valuenow`) so the countdown remains available to AT after the visible text line is replaced.
- **Preserve (A):** segment `role="radio"`/`role="switch"` + `aria-checked`, `role="radiogroup"` labels, `aria-expanded` on the Advanced drawer.
- QR quiet-zone + module colors are frozen for scannability (D2) — an accessibility/contrast pass must NOT "fix" the white QR card.
