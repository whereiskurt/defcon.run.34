Bring v5 PUBLISH to full parity with the 3.1.1 path: uplink ServiceEnvelope decode feeding the
existing InspectorPacket/PacketDecider unchanged, rewrites (hop clamp via RemarshalEnvelope,
payload censoring via RewritePayloadString) that actually reach the v5 wire, a topic-alias

in handleProxyV5. The governing lesson is meshtk#22: a rewrite that mutates the parsed struct
without re-marshalling onto the wire is a silent no-op, so every rewrite assertion here is made
against re-encoded WIRE BYTES, never against struct fields.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| v5 client -> proxy uplink PUBLISH | Attacker-chosen topic, properties, and ServiceEnvelope contents |
| mosquitto -> proxy downlink PUBLISH | Broker fan-out including the connection's own echoed uplinks |
| Rules engine -> MQTT wire | Rewrites must reach the wire or they are security theatre |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-68-02-01 | Tampering | `RewriteHopLimit` / `RewritePayloadString` on v5 | high | mitigate | `setPublishPayload` dispatches onto Raw.MQTT5 and sets `WireRewritten`; the uplink loop re-encodes only when that flag is set; TestV5PublishRewriteReachesTheWire decodes the RE-ENCODED wire payload, exactly the assertion meshtk#22 lacked |
| T-68-02-02 | Tampering / Elevation of Privilege | Topic-aliased uplink PUBLISH | high | mitigate | BLOCK on `Properties.TopicAlias != nil` or empty topic, with `action=BLOCK reason=topic_alias_uplink`; layered under 68-01's TopicAliasMaximum strip in both directions |
| T-68-02-03 | Information Disclosure | Downlink self-echo of a client's own traffic | low | mitigate | `logDownlinkEnvelope` gateway-id comparison; suppression is "do not write the frame", identical semantics to 3.1.1 |
