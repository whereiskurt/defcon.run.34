<objective>
Sync the monorepo's tracked meshtk overlay to upstream main so the production image is built
from the dual-codec code — without reverting anything and without clobbering the con-specific
embedded routes.

This is the highest-risk plan in the phase, and the risk is not the v5 code. It is the overlay
mechanism: `apps/build.sh resolve_meshtk` in CI snapshots every repo-tracked file under
`apps/run.mqtt/meshtk/`, wipes the directory, clones a fresh generic meshtk from GitHub, then
untars the snapshot ON TOP. Tracked monorepo files therefore SHADOW upstream. This worktree's
copy is 36 commits stale (VERSION v0.0.66; `peekConnectProtocolVersion` and `RemarshalEnvelope`
both grep to zero), so a sync performed from this branch would overlay stale server sources onto
a fresh clone and silently REVERT meshtk#22 (hop clamp) and meshtk#23 (the v5 honest reject) in
production.

Purpose: the monorepo half of MQV5-07.
Output: a branch off origin/main whose meshtk overlay mirrors upstream main for every tracked Go
file, leaves `internal/embedded/**` untouched, compiles in a local reproduction of the CI
overlay, and is merged to main.
</objective>
