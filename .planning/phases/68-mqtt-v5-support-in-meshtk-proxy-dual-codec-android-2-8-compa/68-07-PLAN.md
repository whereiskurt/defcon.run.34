<objective>
Close **CR-04**, the last SC3 parity defect and the security-relevant one: on a `v5.ReadPacket`
failure, `handleV5PublishUplink` relays the PUBLISH raw and returns success, skipping — in order —
the topic-alias guard, `inspectV5Publish`, `PacketDecider.Decide`, `RewriteHopLimit`,
`BlockInvalidEncryption` and every Block rule. `paho.golang`'s `Properties.Unpack` hard-errors on
any property id outside its table, so three client-controlled bytes spliced into the properties
block buy a permanent, trivially discoverable inspection exemption. The verifier reproduced it as
PROBE-A: an unclamped `hop_limit=7` NODEINFO envelope reached the backend byte-identical while the
same envelope in a parseable frame was clamped to 3/7. This is fail-open on the exact control that
exists to stop fleet-wide RF flood amplification.

The fix does not weaken the capture-before-parse design, which is correct and load-bearing. It
adds a second, deliberately dumb parser that reads only what the MQTT 5.0 wire format guarantees
is skippable without knowing any property id — topic, optional packet id, property-block length —
and hands topic + payload to the same inspection path. Because that parser knows the payload's
byte offset, a rewrite is applied by splicing the new payload into the captured frame, which
preserves the unmodelled properties exactly and is strictly stronger than a codec round trip.
When even that fails, the packet is refused, which is precisely what the 3.1.1 loop does with a
packet its codec cannot read.

## Why dropping an unreadable PUBLISH does not contradict the locked decision

68-CONTEXT.md locks "unknown/unhandled v5 packet types: forward raw bytes rather than drop". That
decision governs packet types the proxy has no reason to inspect — PINGREQ, PUBACK, DISCONNECT and
anything the codec does not model — and 68-06 preserved it as the explicit `default` arm of the
frame switch. PUBLISH is not one of those: it is a HANDLED type, the only type the rules engine
exists to judge, and VERIFICATION.md prescribes fail-closed for it by name ("do not let a
properties-parse failure buy an inspection exemption"). Relaying a PUBLISH the proxy cannot read is
the defect, not the decision.

## MQTT 5.0 PUBLISH wire layout (the only spec knowledge the parser needs)

```
byte 0            : 0x3 << 4 | DUP<<3 | QoS<<1 | RETAIN
varint            : remaining length (1..4 bytes)
uint16 + n bytes  : topic name
uint16            : packet identifier  -- PRESENT ONLY WHEN QoS > 0
varint            : property block length in bytes
n bytes           : property block   -- SKIPPED WHOLE, never interpreted
remainder         : payload
```

Every field before the payload is length-prefixed, which is why the payload boundary is
computable without knowing what any property means.
