## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → CloudFront (run.defcon.run) | Untrusted viewers, including covert-egg scans, cross here. |
| CloudFront → use1 ALB (app origin) | The covert request is forwarded (cookie + query) to the run.human app. |
| CloudFront behavior list ordering | Path-pattern precedence decides which origin (S3 vs ALB) serves the covert path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-48-01 | Information disclosure | covert `/use1/assets/theme` behavior | high | mitigate | Managed-CachingDisabled ensures no per-user CSS (auth-state-bearing) is cached at the edge and served to another viewer. Encoded in the authored behavior + asserted in DEPLOY-SPEC curl matrix. |
| T-48-02 | Elevation of privilege / routing | behavior ordering vs `/use1/assets/*` S3 wildcard | high | mitigate | Exact behavior authored BEFORE the S3 wildcard (first-match). Mis-order → covert path served cached from S3 (channel dead, no auth). DEPLOY-SPEC requires a `terragrunt plan` diff review confirming only the run distro gains one behavior. |
| T-48-03 | Tampering / blast radius | shared six-domain cloudfront module | medium | mitigate | Behavior gated `each.key == "run"` so the five other production distros are untouched; DEPLOY-SPEC mandates a plan-diff scoped-change check before apply. |
| T-48-04 | Denial of service | CachingDisabled forwards every covert hit to the app | low | accept | Covert path is a single lightweight GET; the run.human app already fronts all `/use1/*` traffic. No new exposure beyond existing app behaviors. |
</threat_model>
