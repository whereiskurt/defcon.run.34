## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → q.defcon.run CloudFront | Untrusted viewers hit both the scan path and the new `/admin/*` path. |
| q CloudFront `/admin/*` → run.human (shared ALB) | Admin request forwarded with the `.defcon.run` session cookie. |
| run.human `ADMIN_GROUPS` gate | The actual authorization decision (`admin`/`runadmin`) lives in run.human, not the resolver. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-48-05 | Elevation of privilege | `q.defcon.run/admin/*` reaching run.human | high | mitigate | Authorization is enforced by run.human's existing `ADMIN_GROUPS` gate; the CloudFront behavior only routes + forwards the cookie. DEPLOY-SPEC mandates verifying non-admin=denied, anon=sign-in before trusting the surface. |
| T-48-06 | Spoofing / routing | Host + basePath rewrite to run.human | high | mitigate | Runtime-decided mechanism documented in DEPLOY-SPEC and apply-tested; not guessed into live-critical HCL. Wrong Host → 404/wrong app, never an auth bypass (the gate still runs on whatever run.human serves). |
| T-48-07 | Information disclosure | caching the gated admin page | high | mitigate | Managed-CachingDisabled on the `/admin/*` behavior — no per-admin leaderboard HTML cached at the edge. |
| T-48-08 | Tampering / availability | turning the resolver into an app server / breaking scans | medium | mitigate | Addition rides the `enable_transport` gate (inert) and leaves the `default_cache_behavior` scan path untouched; DEPLOY-SPEC requires confirming scans still 302 post-apply. |
