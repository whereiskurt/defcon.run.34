  <behavior>
    MECHANISM (resolved-map / floor validation): the migrated server components (SponsorInstructions, ContributionChip) call `loadCopy()` internally and do NOT accept an injected copy map, so this automated test does NOT render them — rendering an async server component that self-fetches copy is impractical in the vitest setup. Instead it validates the exact object that a CMS-down `loadCopy()` returns: the committed snapshot `default` map. This is the equivalence that makes SC-4 hold — when the CMS is unreachable, `loadCopy` falls back to this map, and the server `t(map, key)` therefore resolves every consumed key to real wording rather than echoing the dotted key. The REAL end-to-end server-render SC-4 proof is the live CMS-down human walkthrough in Task 3; this test locks the floor those renders depend on.
    - Import the server resolver `t` from `@/lib/copy` and the snapshot `default` map from `copy-snapshot.json` as `snapshotDefaultMap` (this is byte-identical to the CMS-down `loadCopy('default')` output).
    - Build an explicit list of the bib.* keys consumed by the migrated SERVER surfaces: the `bib.instructions.*` keys (payVia, sendTo, requiredComment, requiredCommentHint, openProvider, reconcileNoteBefore, reconcileNoteAfter, venmoTitle, venmoSubhead, cashappTitle, cashappSubhead, backToBib), `bib.landing.title`, `bib.landing.intro`, and the chip keys `bib.contribution.thanks` + `bib.contribution.chipAria`.
    - For each consumed key, call `t(snapshotDefaultMap, key, vars)` — passing representative `vars` for the interpolated keys (e.g. `{ provider: 'Venmo' }` for payVia/openProvider, `{ amount: '$25.00', providers: 'Venmo' }` for chipAria) — and assert the result is a non-empty string that contains real human wording (spot-check the "Pay via" / "Send to" phrasing and the thank-you text).
    - Assert NO returned string is key-shaped: match `/bib\.[a-z]\w*\./` against each resolved value and assert no match (a naive `toContain('bib.')` is wrong — a legitimate hint may end a sentence with "…your bib."). The dotted-key regex is the correct guard, and a match here means the server `t` echoed the key (the key is absent from the floor → SC-4 broken).
  </behavior>

Do NOT attempt to render the async server components directly (they self-fetch via loadCopy — the real server-render proof is the human check in Task 3).
