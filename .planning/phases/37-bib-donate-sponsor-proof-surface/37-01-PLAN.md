<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| script → Strapi write API | The import script holds a write-capable token that can mutate the copy catalog |
| server → client (React) | Only the resolved copy map may cross into the client bundle; never the CMS token/URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-37-01 | Info-disclosure / Elevation | scripts/import-copy.mjs write token | high | mitigate | `STRAPI_WRITE_TOKEN` read from env at run time only; never defaulted, logged, echoed, added to NEXT_PUBLIC_*, or committed. Verify: `grep -R "STRAPI_WRITE_TOKEN" src/` returns nothing (script-only). |
| T-37-03 | Info-disclosure | server-only @/lib/copy resolver | high | mitigate | Test C asserts no "use client" component imports `@/lib/copy"`; the token stays inside loadCopy on the server. |
| T-37-SC | Tampering | npm/pip/cargo installs | low | accept | No package installs this phase — script uses global fetch, tests use existing vitest. No dependency surface added. |
</threat_model>
