<objective>
Port the RFC 6238/4226 TOTP core from the upstream meshtk Go (`~/working/meshtk/pkg/otp/totp.go`) into a
pure, dependency-free `src/lib/ctf-otp.ts` using Node `crypto`, and add the NEW verify/skew logic the Go
lacks. This is the rotating-OTP primitive the judge dispatches to; it is fully unit-testable in isolation.

Purpose: Rotating-OTP flags need constant-time, skew-tolerant verification of a rolling code. The Go has
generation only — `verifyTotp` (±skew window + `crypto.timingSafeEqual`) is net-new logic proven against
RFC 6238 vectors before the judge wires it in.

Output: `ctf-otp.ts` exporting `parseOtpauth`, `totpAt`, `adjacentCodes`, `verifyTotp`, plus a hand-written
base32 decoder — all unit-tested (RFC vectors parameterized, skew boundaries, constant-time).
</objective>

  <behavior>
    RED first — write these tests before the implementation:
    - RFC 6238 vectors: parameterize the core to the RFC's 30s period / 8-digit SHA1 vectors (secret
      "12345678901234567890" as base32) and assert `totpAt` returns the published codes at the RFC
      timestamps (e.g. 59s, 1111111109s, 20000000000s).
    - period-120 generation: `totpAt` at a fixed unixSeconds with period 120 / 6 digits returns a stable
      6-digit code (cross-checkable against a meshtk Go harness; pin the observed value).
    - verifyTotp skew boundary: with skew=1, a guess equal to the previous/current/next-period code
      verifies true; a code two periods away verifies false; a wrong-length / non-numeric guess is false.
    - constant-time: verifyTotp routes its final compare through `crypto.timingSafeEqual` (length-guarded).
    - parseOtpauth: parses `otpauth://totp/Label?secret=...&period=120&digits=6&issuer=...`; applies
      defaults digits 6 / period 120 / SHA1 / issuer "Defcon.run" when query params are absent; rejects a
      non-otpauth scheme / missing secret.
    - adjacentCodes: returns previous/current/next codes for the window straddling `now` plus a
      remainingSeconds in `[1, period]`.
  </behavior>
  <implementation>
    Implement `ctf-otp.ts` as a pure module (only `node:crypto` imports; no electro, no DOM). Port the Go
    core: base32 decode (uppercase-normalize, strip spaces, `=`-pad to a multiple of 8, decode to bytes —
    hand-written since Node has no base32); `totpAt(secret, unixSeconds, {digits=6, period=120})` computing
    counter = floor(unixSeconds/period), big-endian 8-byte counter, `createHmac("sha1", key)`, dynamic
    truncation, mod 10^digits, zero-padded to `digits`. Leave a `switch` on algorithm with only SHA1 wired
    (documented seam for SHA256/512). `parseOtpauth(url)` via the WHATWG `URL` parser returning
    `{secret,digits,period,algorithm,label,issuer}` with the Go defaults. `adjacentCodes(secret, now, opts)`
    returning `{previous,current,next,remainingSeconds}`. `verifyTotp(secret, guess, now, {digits,period,skew=1})`
    — NEW: generate the code for each offset in `[-skew..+skew]`, compare each against the guess with a
    length-guarded `crypto.timingSafeEqual`, OR the results; never throw (return false on any decode error).
    NEVER log the secret or the guess.
  </implementation>
