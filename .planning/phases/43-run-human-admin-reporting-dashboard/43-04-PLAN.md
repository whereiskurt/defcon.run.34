<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser (any user) → /api/admin/users | Untrusted request; must pass the shared admin gate + fresh-claims revalidation. |
| server assembly → JSON response to client | PII (emails) crosses here; must be masked unless explicitly revealed. |
| admin → CSV download | Full emails/QR/bib codes leave the server behind the same gate. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-43-01 | Elevation of privilege | users route gate | high | mitigate | requireAdmin (services) + synchronous revalidateAdmin on every request; denial → bare 404. |
| T-43-02 | Information disclosure (route existence) | denial path | medium | mitigate | Every denial returns `new Response(null, { status: 404 })` — no 403, no error body advertising the route. |
| T-43-03 | Information disclosure (PII) | JSON payload + CSV | high | mitigate | JSON masks emails (maskEmail); full email only for the explicitly revealed row. CSV carries full data but only behind the admin gate + no-store. No unrevealed full-email column ever serialized to the client. |
| T-43-04 | Information disclosure (email enumeration) | ?q search | medium | mitigate | Search runs server-side over already-authorized data behind the admin gate; no unauthenticated access; returns matching rows, not a "does this email exist" oracle to non-admins. |
| T-43-SC | Tampering (supply chain) | dependencies | n/a | accept | No new npm packages (CSV escaping hand-rolled via copied csvCell/toCsv). No legitimacy gate required. |
</threat_model>
