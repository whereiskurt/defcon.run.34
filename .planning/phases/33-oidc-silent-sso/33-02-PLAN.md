Output: `lib/silent-sso.ts` (pure helpers), initiator + fallback routes, the `/silent-callback` bridge page, the `SilentSSO` iframe host component, mounted in gpx and with `pages.error` routed to the bridge.

LOCKED CONTRACT NOTE (do NOT "fix" toward the spec's Data Flow Case 2): the parent's `login_required` behavior is **stay-logged-out**, with the redirect fallback armed ONLY on timeout (no message within `SILENT_SSO_TIMEOUT_MS`). This follows the LOCKED CONTEXT decision (33-CONTEXT.md lines 61-66) and the spec Contract lines 137-139. The spec's Data Flow "Case 2" narrative (login_required → immediate redirect fallback) is a contradictory edge-case description; an executor cross-reading it must NOT change the code to redirect on `login_required`. `decideParentAction` maps login_required → `"stay-logged-out"`; only the timeout path navigates to the fallback route.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| iframe (auth.defcon.run responses) → parent (gpx) | Cross-frame `postMessage` from the bridge to the parent listener |
| bridge page → parent window | The only channel that reports silent-SSO outcome |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-33-04 | Spoofing | parent message listener | high | mitigate | `decideParentAction` returns ignore unless `event.origin === window.location.origin` AND the message type matches; the parent never acts on foreign-origin messages. |
| T-33-05 | Information Disclosure | bridge postMessage target | high | mitigate | The bridge posts to `window.location.origin` explicitly, never `"*"` — the message cannot leak to an unintended embedder. |
| T-33-06 | Denial of Service | hung/blocked iframe | medium | mitigate | A ~4.5s timeout tears down the iframe and downgrades to the invisible redirect fallback; the user is never left waiting on a silent frame. |
| T-33-07 | Elevation of Privilege | prompt=none negatives | medium | mitigate | Every negative (`login_required`/`interaction_required`/`consent_required`/`access_denied`) is normalized to login_required by `resolveSilentStatus`; no OIDC error is surfaced and no auto-redirect occurs for a genuinely logged-out user. |
</threat_model>
