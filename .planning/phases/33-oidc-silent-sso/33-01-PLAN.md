<objective>
Apply the three IdP (run.auth) changes that make an authenticated OIDC interaction complete server-side with no page render, auto-consent first-party clients so `prompt=none` succeeds, and persist the provider SSO `_session`.

Purpose: This is the IdP half of Approach A. Without it, a `prompt=none` request from a warm RP fails with `consent_required` and the provider session never persists across browser restarts.
Output: Repointed `interactions.url`, a testable `makeLoadExistingGrant` factory wired into the provider config, `remember:true` on both login branches, and a unit test proving the auto-consent decision.
</objective>

    Create `src/config/load-existing-grant.ts` exporting `makeLoadExistingGrant(deps)` where deps = `{ firstPartyClientIds: string[]; createGrant: (a: { accountId: string; clientId: string; scope?: string }) => Promise<string> }`. It returns an async `loadExistingGrant(ctx)` hook that: reads `ctx.oidc.account`, `ctx.oidc.client?.clientId`, `ctx.oidc.params?.scope`, `ctx.oidc.session`; returns undefined when there is no account or the clientId is not in `firstPartyClientIds`; otherwise looks up an existing grant id via `ctx.oidc.session.grantIdFor(clientId)` and, when present, loads/returns it; when absent, calls `deps.createGrant({ accountId, clientId, scope })`, records it with `ctx.oidc.session.ensureGrantId(clientId, grantId)`, and returns the loaded grant. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| RP → IdP authorize (`prompt=none`) | Untrusted client_id + scope reach the provider; loadExistingGrant decides auto-consent |
| Browser session → IdP interaction route | `sess_auth` JWT presented; server completes interaction and mints grant |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-33-01 | Elevation of Privilege | loadExistingGrant auto-consent | high | mitigate | Auto-consent is bounded to `Object.values(config.oidc.clients)` (the registered first-party allowlist); any unknown client_id returns undefined. Unit test Task 3 case (a) proves the allowlist boundary. |
| T-33-02 | Information Disclosure | grant scope on mint | medium | mitigate | The minted grant covers only `ctx.oidc.params.scope` (the requested scopes), mirroring the existing [uid].ts grant body; no broadening. |
| T-33-03 | Repudiation / Session persistence | remember:true (15-day Session TTL) | medium | accept | Longer SSO window is a deliberate locked tradeoff; existing rpInitiatedLogout still clears both provider `_session` and `sess_auth`, so logout remains complete. |
| T-33-SC | Tampering | npm devDependency (vitest) | low | accept | No NEW third-party package introduced — `vitest` reuses the exact version already locked in run.bib (in-repo vetted). No install checkpoint required. |
</threat_model>
