Create a new `CheckInModal.tsx` component that implements a two-phase GPS check-in modal.

**Component signature:**
```typescript
interface CheckInModalProps {
  isOpen: boolean;
  onClose: () => void;
  checkinPreference?: string; // "public" or "private"
  onCheckInComplete?: () => void; // callback after successful check-in
}
export default function CheckInModal({ isOpen, onClose, checkinPreference, onCheckInComplete }: CheckInModalProps)
```

**State management:**
- `phase`: "collecting" | "ready" | "submitting" | "success" | "error"
- `samples`: array of `{ latitude, longitude, accuracy, timestamp }` objects
- `sampleCount`: number (0-3) for progress display
- `bestAccuracy`: number | null
- `isPrivate`: boolean (initialized from `checkinPreference === "private"`)
- `quotaRemaining`: number | null (set from POST response)
- `errorMessage`: string | null

**Phase 1 - Collecting (starts immediately when `isOpen` becomes true):**
- Use `navigator.geolocation.getCurrentPosition()` called 3 times at ~667ms intervals (via setTimeout)
- Show HeroUI `Progress` component: value = `(sampleCount / 3) * 100`, color="primary", label="Collecting GPS...", showValueLabel with `${sampleCount}/3`
- On each successful position: push `{ latitude, longitude, accuracy, timestamp: Date.now() }` to samples, increment sampleCount
- When 3 samples collected: compute bestAccuracy = `Math.min(...samples.map(s => s.accuracy))`, transition to "ready" phase
- On geolocation error (permission denied or unavailable): set phase to "error", errorMessage = "Location unavailable -- enable GPS and try again"
- Use a ref to track whether modal is still open to avoid state updates after unmount/close

**Phase 2 - Ready to submit:**
- Show success line: "Location captured (+/-{bestAccuracy}m)" with accuracy rounded to nearest integer
- HeroUI `Switch` for privacy toggle: `isSelected={isPrivate}`, `onValueChange={setIsPrivate}`, with dynamic label showing "Private" when selected, "Public" when not
- Quota display as small muted text: "Check-ins used today" (quota info comes back after submit -- show it in success phase)
- Cancel and "Check In" buttons. "Check In" button uses `color="success"` and `isLoading={phase === "submitting"}`

**Submit flow (phase = "submitting"):**
- POST to `apiUrl('/api/checkins')` with body: `{ samples, source: "Web GPS", isPrivate }`
- On 201 success: set phase to "success", extract `quota.remaining` from response
- Show "Checked in!" with remaining quota count for 1.5 seconds (setTimeout), then call `onClose()` and `onCheckInComplete?.()`, reset all state
- On non-quota error: set phase to "error", errorMessage = "Something went wrong", show Retry and Cancel buttons. Retry re-attempts POST with same samples (no re-collection).
- On quota error (429): set phase to "error", errorMessage = "Check-in limit reached for today"

**Reset behavior:**
- When modal closes (onClose or auto-close after success), reset all state to initial values
- Use `useEffect` watching `isOpen`: when it becomes true, reset state and start GPS collection; when false, clear any pending timeouts

**HeroUI Modal props:** `size="sm"`, `placement="center"`, `backdrop="blur"`, `isDismissable={phase !== "submitting"}`, `onClose={handleClose}` where handleClose only works if not submitting.

**Imports needed:** Modal, ModalContent, ModalHeader, ModalBody, ModalFooter, Button, Progress, Switch from '@heroui/react'; apiUrl from '@/lib/api'; useState, useEffect, useRef, useCallback from 'react'.

Mark as 'use client' at top of file.
