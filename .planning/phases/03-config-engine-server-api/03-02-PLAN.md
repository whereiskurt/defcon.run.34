3. **Retry logic for connection:** After the 4s initial delay, wrap `device.configure()` in a retry loop — try up to 3 times with 2s delay between attempts. The freshly-flashed device may take varying time to initialize.

4. **MeshDevice in wrapper, not exported:** Store the MeshDevice reference internally. Export only the wrapper functions. This keeps the @meshtastic/core API encapsulated (like esptool.ts encapsulates esptool-js).

5. **Error messages:** Translate library errors to user-actionable messages, similar to `getConnectionErrorMessage` in esptool.ts.

Create `src/hooks/use-configure.ts` — React hook that orchestrates the full config pipeline: disconnect esptool transport → reconnect via @meshtastic/core → fetch config from /api/config → push all config → report progress.

Follow the useFlash hook pattern: expose progress state + action function + reset.

```typescript
"use client";

import { useState, useCallback, useRef, useEffect } from "react";
import type { ConfigProgress } from "@/types/config";
import { INITIAL_CONFIG_PROGRESS } from "@/types/config";
import type { DeviceConfigPayload, ConfigStage } from "@/types/config";
import {
  connectMeshtasticDevice,
  pushDeviceConfig,
  disconnectMeshtasticDevice,
} from "@/lib/meshtastic";

interface UseConfigureReturn {
  /** Current config push progress */
  progress: ConfigProgress;
  /** Whether config push is in progress */
  isConfiguring: boolean;
  /** Whether config push completed successfully */
  isComplete: boolean;
  /** Whether config push encountered an error */
  isError: boolean;
  /** The config payload (available after successful fetch, for Done screen display) */
  configPayload: DeviceConfigPayload | null;
  /**
   * Start the configure pipeline:
   * 1. Disconnect esptool transport
   * 2. Reconnect via @meshtastic/core (with reboot delay + retry)
   * 3. Fetch config from /api/config
   * 4. Push MQTT → Channels → Identity → Radio → Commit
   *
   * @param disconnectTransport - Function to disconnect the esptool transport (from useSerial)
   */
  configure: (disconnectTransport: () => Promise<void>) => Promise<void>;
  /** Reset config state to idle (for retry) */
  reset: () => void;
}

export function useConfigure(): UseConfigureReturn {
  const [progress, setProgress] = useState<ConfigProgress>(INITIAL_CONFIG_PROGRESS);
  const [configPayload, setConfigPayload] = useState<DeviceConfigPayload | null>(null);
  const isConfiguringRef = useRef(false);
  const deviceRef = useRef</* MeshDevice type */ any>(null);

  const configure = useCallback(async (disconnectTransport: () => Promise<void>) => {
    if (isConfiguringRef.current) return;
    isConfiguringRef.current = true;

    try {
      // Stage 1: Disconnect esptool transport to release serial port
      setProgress({
        stage: "connecting",
        completedStages: [],
        stageSummaries: {},
        error: null,
      });

      await disconnectTransport();

      // Stage 2: Reconnect via @meshtastic/core (handles reboot delay + retry)
      const device = await connectMeshtasticDevice();
      deviceRef.current = device;

      setProgress(prev => ({
        ...prev,
        completedStages: [...prev.completedStages, "connecting"],
        stageSummaries: { ...prev.stageSummaries, connecting: "Device connected" },
      }));

      // Stage 3: Fetch config from /api/config
      const response = await fetch("/api/config");
      if (!response.ok) {
        const err = await response.json().catch(() => ({ error: "Unknown error" }));
        throw new Error(err.error || `Config fetch failed (HTTP ${response.status})`);
      }
      const config: DeviceConfigPayload = await response.json();
      setConfigPayload(config);

      // Stage 4: Push config with progress callbacks
      // Update stage before each push, callback marks completion
      const stages: ConfigStage[] = ["mqtt", "channels", "identity", "radio", "committing"];
      let currentStageIndex = 0;

      const onStageComplete = (stage: string, summary: string) => {
        setProgress(prev => ({
          ...prev,
          stage: stages[currentStageIndex + 1] || "complete",
          completedStages: [...prev.completedStages, stage as ConfigStage],
          stageSummaries: { ...prev.stageSummaries, [stage]: summary },
        }));
        currentStageIndex++;
      };

      // Set first stage
      setProgress(prev => ({ ...prev, stage: "mqtt" }));

      await pushDeviceConfig(device, config, onStageComplete);

      // All done
      setProgress(prev => ({
        ...prev,
        stage: "complete",
        completedStages: [...prev.completedStages],
      }));

    } catch (err) {
      const message = err instanceof Error ? err.message : "Configuration failed";
      setProgress(prev => ({
        ...prev,
        stage: "error",
        error: message,
      }));
    } finally {
      // Disconnect device
      if (deviceRef.current) {
        await disconnectMeshtasticDevice(deviceRef.current).catch(() => {});
        deviceRef.current = null;
      }
      isConfiguringRef.current = false;
    }
  }, []);

  const reset = useCallback(() => {
    setProgress(INITIAL_CONFIG_PROGRESS);
    setConfigPayload(null);
    isConfiguringRef.current = false;
  }, []);

  // Cleanup on unmount
  useEffect(() => {
    return () => {
      if (deviceRef.current) {
        disconnectMeshtasticDevice(deviceRef.current).catch(() => {});
      }
    };
  }, []);

  const activeStages: ConfigStage[] = ["connecting", "mqtt", "channels", "identity", "radio", "committing"];

  return {
    progress,
    isConfiguring: activeStages.includes(progress.stage),
    isComplete: progress.stage === "complete",
    isError: progress.stage === "error",
    configPayload,
    configure,
    reset,
  };
}
```

**Key design decisions:**

1. **MeshDevice in useRef (not useState):** Same pattern as ESPLoader in useSerial — mutable class instances must be in refs. Per accumulated decision from Phase 2.

2. **disconnectTransport parameter:** The configure function accepts a callback to disconnect the esptool transport. This avoids the hook needing to know about esptool internals — WizardContainer passes `serial.disconnect`.

3. **configPayload stored:** The fetched config is stored so the Done screen can display the config summary (long name, short name, MQTT server, channels, radio region).

4. **Fail-fast:** Per CONTEXT.md locked decision, any step failure fails the entire config. No partial recovery — user retries from scratch.

5. **Cleanup on unmount:** Disconnects MeshDevice if component unmounts mid-config.

6. **Real-time speed:** Per CONTEXT.md locked decision, no artificial delays. Each config pushes as fast as the device accepts.
