<objective>
Add the `CtfCode` ElectroDB entity — the storage substrate for Slice-3 wordlist one-time codes (CTFT-12). One row per `(challenge, codeHash)`; a claim later flips `claimedBy`/`claimedAt` atomically. Plaintext codes are NEVER stored — only the salted `codeHash` (same salt scheme as answers). This plan is schema-only: no DB-mutating helpers, no judge wiring (that is 56-02), no form (56-03).

Purpose: Establish the single-use code substrate + its pinned key contract so the judge (56-02) and the admin bulk-load (56-03) can both build on a stable `(challenge, codeHash)` key.
Output: `CtfCode` entity + `CtfCodeItem` type in `entities/ctf.ts`; CtfCode key-parity assertions in `ctf-key-parity.test.ts`.
</objective>
