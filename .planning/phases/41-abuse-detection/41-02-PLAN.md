  <action>
    Author q1_sustained_activity.sql as a parameterized Athena (Trino/Presto SQL) query. Use these exact placeholder tokens (the handler in Plan 04 does a literal string replace): `{database}`, `{table}`, `{lookback_hours}`, `{session_gap_min}`, `{session_hours}`. Reference only columns declared by Plan 01's Glue table: `client_ip`, `user_agent`, `request_verb`, `request_url`, `elb_status_code`, `time`, and the projected partition column `day`.

    Logic (Presto): parse `time` (ISO8601) with `from_iso8601_timestamp`; restrict rows to the recent window using BOTH the projected `day` partition (>= the day of now minus the lookback, to prune scanned partitions) AND `from_iso8601_timestamp(time) >= now() - interval '{lookback_hours}' hour`. Per `client_ip`, order by event time and use `lag()` over a window partitioned by `client_ip` ordered by time to compute the gap to the previous request; mark a new session boundary when that gap exceeds `{session_gap_min}` minutes; assign a session id via a running `sum()` of the boundary flag; group by `client_ip, session_id` to get each session's `min(time)`/`max(time)` span; then aggregate per `client_ip` to the MAX session span. Flag rows whose max session span in minutes >= `{session_hours}` * 60.

    Final SELECT returns one row per flagged `client_ip` with: `client_ip`, `array_agg(distinct user_agent)` as `user_agents`, total `request_count`, `first_seen`, `last_seen`, `max_session_minutes`, top-N `request_url` (approx_most_frequent or a grouped count, cap N=10) as `top_paths`, and a status-code mix summary (counts of 2xx/4xx/5xx from `elb_status_code`). Order by `max_session_minutes` desc. The result MUST carry both identifiers (client_ip AND user_agents) per the AD-03/AD-04 requirement that every finding surfaces IP + UA.

    Do NOT interpolate any request-log field into SQL text — only the numeric/identifier placeholders above are substituted. Write README.md in this dir documenting the placeholder contract and that the handler substitutes them, plus a one-line note that these queries are validated end-to-end against a synthetic partition in the Plan 05 deploy checkpoint (not in CI, which would require a live Athena/Glue).
  </action>

    Logic (Presto): restrict to the recent window via the `day` partition AND `from_iso8601_timestamp(time) >= now() - interval '{lookback_hours}' hour`.     Final SELECT returns one row per flagged `client_ip`: `client_ip`, `array_agg(distinct user_agent)` as `user_agents`, a method-mix summary (counts by `request_verb`), `peak_5min_bucket` (the window start), `peak_requests_5min`, `peak_posts_5min`, top-N `request_url` (N=10) as `top_paths`, and the 4xx/5xx ratio derived from `elb_status_code`. Order by greatest(peak_posts_5min, peak_requests_5min) desc. Every row carries client_ip AND user_agents.

    Only the numeric/identifier placeholders are substituted; no request-log field is ever interpolated into SQL text.
