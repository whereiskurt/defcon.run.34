<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Athena result rows → finding/email/JSONL | Attacker-controlled UA/URL strings flow into SNS email + findings.jsonl; must be allow-listed + length-capped. |
| Handler → dedup store | Escalation decisions depend on prior state; must fail-safe on read/write error. |
| Handler → reused SNS topic | Publishes to the Phase 40 operator inbox. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-41-07 | Information Disclosure | finding JSONL / SNS email | low | mitigate | `buildFinding` allow-lists exactly the schema fields and caps user_agents(<=5) / top_paths(<=10) / string lengths, so nothing unbounded or unexpected leaks into email or the seam file. |
| T-41-08 | Denial of Service | schedule reliability | medium | mitigate | Handler wraps all work in try/catch and NEVER throws; Athena failure logs + retries next cron; dedup-write failure still alerts (fail-safe). Proven by unit tests. |
| T-41-13 | Tampering | template/param mismatch | low | mitigate | `renderQuery` throws if any `{...}` remains, so a placeholder mismatch fails loudly in CI tests, never producing a malformed live query. |
| T-41-SC | Tampering | npm/pip/cargo installs | low | accept | Zero third-party packages: AWS SDK v3 is runtime-provided; tests use node:test builtins. No legitimacy gate applies. |
</threat_model>
