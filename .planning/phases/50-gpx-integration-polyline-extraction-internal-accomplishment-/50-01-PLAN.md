<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| run.gpx → run.human internal endpoint | Server-to-server POST carrying an OIDC sub + polyline; the AUTH_INTERNAL_SECRET is the only credential. |
| public internet → /api/internal/accomplishment | The route is reachable; the secret gate is the sole authorization. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-50-01 | Spoofing | POST /api/internal/accomplishment | high | mitigate | Reject any request whose `x-internal-secret` header !== config.auth.internalSecret with 403 before parsing/data access (copied from the proven internal user route). |
| T-50-02 | Tampering | `oidcSub` in body scores an arbitrary user | medium | accept | Any secret-holder can post any sub by design (run.gpx already verified the file owner). The secret IS the boundary; documented, not user-reachable. |
| T-50-03 | Elevation of privilege | body injects `source:"ctf"`/`qr` | medium | mitigate | Source is server-fixed to `"gpx"` inside buildGpxAccomplishmentInput; the body's source (if any) is ignored — preserves the LDBR-12 CTF write boundary. |
| T-50-04 | Info disclosure | benign-drop / error logs | low | mitigate | Log gpxFileId + a message only; never log the secret or full body. |
| T-50-05 | Denial of service | oversized polyline in body | low | accept | Producer (Plan 50-02) decimates to ~100 points before POST; internal-only traffic behind the secret gate. |
| T-50-SC | Tampering | npm/pip/cargo installs | n/a | accept | No new package installs this phase — all imports (@aws-sdk, electrodb, next) already present. No legitimacy gate required. |
</threat_model>
