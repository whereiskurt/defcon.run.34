    Create `apps/run.human/webapp/src/entities/checkin.ts` by porting from DCR33's `checkin.ts` with these adaptations:

    **Entity definition:**
    - `model: { entity: 'CheckIn', version: '1', service: 'run' }` — match RunUser's service
    - Use `electroClient` and `ELECTRO_TABLE` from `./client` (not a separate client like DCR33)
    - All attributes from DCR33: userId, checkInId, timestamp, source, samples (type: 'any'), averageCoordinates (map with lat/lng), bestAccuracy, userAgent, isPrivate (default: true), checkInType (enum: ['Basic', 'OTP', 'With Flag', 'Manual'], default: 'Basic'), otpCode, flagText, geoHash, s3Key, pointsCount, duration, distance, createdAt (readOnly, default: Date.now()), updatedAt (watch: '*', set: Date.now())

    **Indexes (per CONTEXT.md decisions — use gsi2 + gsi3, NOT gsi1):**
    - `primary`: pk composite: ['userId'], sk composite: ['timestamp', 'checkInId']
    - `byGlobalRecent`: index: 'gsi2pk-gsi2sk-index', pk template: 'TYPE#CHECKIN' (composite: []), sk composite: ['timestamp']
    - `byUserRecent`: index: 'gsi3pk-gsi3sk-index', pk composite: ['userId'], sk composite: ['timestamp']

    **GPSSample interface:** Port from DCR33 — latitude, longitude, accuracy, altitude (nullable), altitudeAccuracy (nullable), heading (nullable), speed (nullable), timestamp.

    **CheckInData interface:** source, samples (GPSSample[]), userAgent?, isPrivate?, checkInType?, otpCode?, flagText?

    **Helper functions (all use userId, NOT email — DCR34 difference from DCR33):**

    1. `createCheckIn(userId: string, data: CheckInData)` — Validate samples array non-empty, compute avgLat/avgLng, bestAccuracy (Math.min of accuracies), duration (last - first timestamp in seconds), generate checkInId via crypto.randomUUID(), create entity, then call `RunUser.patch({ userId }).set({ lastCheckInAt: timestamp, checkInCount: ... }).add({ checkInCount: 1 }).go()` for side-effect. NOTE: Use ElectroDB's `add` operation for atomic increment of checkInCount, and `set` for lastCheckInAt. Return created check-in data.

    2. `getCheckInsByUser(userId: string, limit?: number, cursor?: string)` — Query byUserRecent with order: 'desc', return { data, cursor }.

    3. `getRecentCheckIns(limit?: number, cursor?: string)` — Query byGlobalRecent with order: 'desc', return { data, cursor }.

    4. `getCheckIn(userId: string, timestamp: number, checkInId: string)` — Get by primary key composite.

    5. `deleteCheckIn(userId: string, timestamp: number, checkInId: string)` — Delete by primary key, then `RunUser.patch({ userId }).subtract({ checkInCount: 1 }).go()` for side-effect decrement. Use subtract for atomic decrement.

    6. `updateCheckInPrivacy(userId: string, timestamp: number, checkInId: string, isPrivate: boolean)` — Update isPrivate field on check-in. No ownership verification needed at entity layer (API layer handles that in Phase 11).

    **Important differences from DCR33:**
    - No quota logic in entity helpers (centralized in run.auth quota-middleware, used in Phase 11 API routes)
    - No cache invalidation (DCR34 doesn't use the same cache pattern)
    - userId-based lookups throughout (not email-based)
    - GSI indexes shifted to gsi2/gsi3 to avoid collision with RunUser's gsi1

    Export: CheckIn entity, GPSSample interface, CheckInData interface, all helper functions, and the inferred CheckInItem type (`EntityItem<typeof CheckIn>`).
