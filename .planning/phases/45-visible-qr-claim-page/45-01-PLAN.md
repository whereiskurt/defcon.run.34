<objective>
Build the reusable, hygienic park-and-claim data helpers (`createPending` / `claimPending`) and the small judge seam they require, so an unauthenticated QR scan can be parked against a nonce and later credited exactly once through the SINGLE Phase-44 `judgeSolve` flow. Phase 46 (covert channel) reuses these helpers verbatim — build them reusable and channel-agnostic.

Purpose: CTF-06 needs the anon scan to park a hash (never the raw guess) and the later signed-in visit to redeem that nonce with idempotent credit. Phase 44 stores `CtfPending` schema-only and `judgeSolve` validates a RAW guess — but the parked row deliberately holds only `submittedFlagHash`. This plan bridges that seam (a pre-hashed guess path into `judgeSolve`) and adds the pending helpers on top.

Output: `src/lib/ctf-pending.ts` (createPending/claimPending), an additive `verifyAnswerHash` in `ctf-hash.ts`, an additive `guessHash` input branch in `judgeSolve`, and vitest proof (idempotency, hygiene, TTL) — all `tsc`-clean and green.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-45-01 | Information disclosure | createPending storage + logs | high | mitigate | Store ONLY `submittedFlagHash = hashAnswer(guess)`; never persist or log the raw guess. Assert in test (raw guess absent from stored row and from logs). |
| T-45-02 | Elevation of privilege | claimPending double-credit | high | mitigate | Credit only through `judgeSolve` (conditional-put idempotency); delete the pending row on claim; re-claim of a spent/absent nonce no-ops. Proven by the double-claim test. |
| T-45-03 | Spoofing | guessHash acceptance in judgeSolve | medium | accept | A caller could pass an arbitrary `guessHash`; it still must equal `Ctf.answerHash` to solve, which is exactly the existing knowledge check (a raw-guess caller has the same power). No new authority granted. |
| T-45-04 | Tampering | nonce forgery | low | accept | `nonce` is an unguessable random UUID and only maps to an already-parked hash; a forged nonce finds no row → no-op. TTL bounds the window. |
</threat_model>
