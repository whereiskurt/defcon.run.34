  <files>apps/run.human/webapp/src/lib/leaderboard-data.ts</files>
  <action>
    Implement the pure core. Reuse Phase-49 scoring — import `rankComparator` and `globalScore` from `@/lib/leaderboard-scoring` (per 51-CONTEXT LOCKED decision "reuse, don't rebuild"); do NOT re-derive any sort or score.

    Types:
    - `LeaderboardUser` — the input row shape. Define it as a superset of the scoring `ScorableUser` PLUS the display fields the board needs: `userId: string`, optional `displayName`, optional `mqttUsertype` (reuse `RunUserItem["mqttUsertype"]` from `@/entities/run-user`), `activityScore?`, `activityCounts?: { checkin?: number; gpx?: number }`, `latestActivityAt?`, `createdAt?`, `ctfScore?: number`, `ctfSolves?: number`. Every field except userId is optional so a plain `RunUserItem` scan row (which does not yet declare ctfScore/ctfSolves — those are CTF-owned per LDBR-12) is assignable to it with zero casts. This assignability is what keeps the plan-02 route tsc-clean.
    - `LeaderboardRow` — the lean output DTO: `globalRank`, `userId`, `displayName`, `mqttUsertype`, `globalScore`, `activityCounts: { checkin: number; gpx: number }`, `ctfSolves` (number). NO email/PII field (threat parity with T-49-04).
    - `LeaderboardResult` — `{ rows: LeaderboardRow[]; total: number; page: number; limit: number }`.

    `buildLeaderboard(users, opts)`:
    1. Sort a COPY of `users` with `rankComparator` (never mutate the input array).
    2. Map the sorted list to DTOs, assigning `globalRank = index + 1` — this is the rank over the FULL sorted set (per 51-CONTEXT specifics + SC #2). Compute `globalScore` via the imported `globalScore(u)`; normalize `activityCounts` to `{ checkin: u.activityCounts?.checkin ?? 0, gpx: u.activityCounts?.gpx ?? 0 }`; `ctfSolves = u.ctfSolves ?? 0`.
    3. Apply the display filter AFTER ranking: when `filter` is a non-empty string, keep rows whose `displayName` (lowercased, `?? ""`) includes the lowercased filter. Filter narrows display, never rank (Claude's-discretion decision: case-insensitive displayName contains).
    4. `total = filtered.length`. Page/limit defaults: `page = opts.page ?? 1` (min 1), `limit = opts.limit ?? 25`. Slice `filtered` at `(page-1)*limit` for `limit` items.
    5. Return `{ rows: slice, total, page, limit }`.

    Cache-staleness primitives (used by plan 02's cache wrapper): export `LEADERBOARD_CACHE_TTL_MS = 60_000` (named constant, DC33 60s parity) and a PURE `isStale(now: number, fetchedAt: number, ttl = LEADERBOARD_CACHE_TTL_MS): boolean` returning `now - fetchedAt > ttl` (strictly greater — at exactly TTL it is still fresh).

    Keep the module free of any DynamoDB/entity/network import (scoring + the RunUserItem TYPE import only). Document the privacy note that this core carries no PII.
  </action>
