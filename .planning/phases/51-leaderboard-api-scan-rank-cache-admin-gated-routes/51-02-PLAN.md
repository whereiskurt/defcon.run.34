<objective>
Ship `GET /api/leaderboard` — the main admin-gated board endpoint — plus the 60s stale-while-revalidate scan cache it sits on. The route is a thin shell: gate (404 non-disclosure + fresh claims) → cached `scanAllRunUsers` → `buildLeaderboard` (plan 01) → JSON. The cache ports DC33's mechanism (`app/api/leaderboard/route.ts`): cold call populates synchronously, within-TTL calls serve cached, past-TTL calls serve stale + kick a background refresh so no request blocks on the scan.

Purpose: A full-table RunUser scan on every board load would be slow and hammer DynamoDB. DC33 solved this with a 60s in-memory cache that never blocks a request on a refresh. This ports that behavior and wires the scan → rank → paginate pipeline behind the same admin gate the Phase-43 dashboard uses.
Output: `lib/leaderboard-cache.ts` (getCachedScan + test-only reset) + `app/api/leaderboard/route.ts` + vitests for both.
</objective>
