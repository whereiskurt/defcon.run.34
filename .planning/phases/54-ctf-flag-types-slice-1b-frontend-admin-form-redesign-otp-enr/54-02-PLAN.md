<objective>
Give the client reward renderer (Plan 54-03) a browser-safe way to compute the rolling OTP codes WITHOUT a new dependency and WITHOUT changing any Phase-53 backend contract. The shipped `ctf-otp.ts` imports `node:crypto` and cannot run in a "use client" bundle. Split its pure primitives into a dependency-free `ctf-otp-core.ts` (re-exported from `ctf-otp.ts` so every existing server import and test keeps working unchanged), and add `ctf-otp-client.ts` exposing `adjacentCodesAsync` that reuses the core primitives with the Web Crypto API (`crypto.subtle`, HMAC-SHA1) for the one platform-specific step.

Purpose: Reuse the audited TOTP logic on the client (base32 decode, dynamic truncation, otpauth parsing) rather than re-implementing it, while keeping the server's synchronous `totpAt`/`verifyTotp`/`adjacentCodes` signatures byte-for-behavior intact (the "additive only — no Phase-53 contract changes" invariant). WebCrypto `crypto.subtle` is confirmed available in the vitest node env, so `adjacentCodesAsync` is unit-testable for parity against the sync path and against RFC 6238 vectors.
Output: `ctf-otp-core.ts`, `ctf-otp-client.ts`, re-export edit to `ctf-otp.ts`, and the client test file.
</objective>
