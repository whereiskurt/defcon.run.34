<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser → server (ctf_upsert) | The admin authors the answer, OTP secret, and reward otpauth; they are hashed/stored server-side and are write-only |
| server edit page → client form prop | A loaded flag row is serialized to the client form; secrets must be stripped first |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-54-04-01 | Information disclosure | edit page prop / raw effect prefill | high | mitigate | Edit page passes redactCtfSecrets(record) (54-01); answer, otp secret, and reward-otpauth are never prefilled on edit; the raw Effect JSON follows the same blank-keeps-stored rule so no secret round-trips (SC-2) |
| T-54-04-02 | Tampering | preset overwrites manual knobs | low | mitigate | Presets pre-fill via presetToAdvanced but never lock the Advanced knobs; the admin can override every value after picking a preset (SC-1) |
| T-54-04-03 | Tampering | no-clobber save regression | medium | mitigate | onSave omits answer/otp/effect when blank so a partial edit preserves the stored secret/reward (mirrors the shipped ctfAttributes no-clobber contract) |
| T-54-04-SC | Tampering | package installs | low | accept | No package installs; the reveal preview reuses the already-present qrcode dep via CtfOtpEnroll |
</threat_model>
