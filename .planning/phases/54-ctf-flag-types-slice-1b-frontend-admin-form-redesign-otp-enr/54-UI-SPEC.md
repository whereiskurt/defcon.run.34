# Phase 54 — UI Design Contract

> Visual and interaction contract for the CTF flag-types Slice 1b frontend: the redesigned admin `CtfForm.tsx` (design "A") and the new player-facing `otp-enroll` reward renderer. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Design-system posture (locked, autonomous):** run.human already ships an established HeroUI + Tailwind 4 design system. The `/admin/qr` surface has a canonical token file — `src/components/admin/qr-ui.ts` (`cls.*` class strings on HeroUI semantic tokens). This phase MUST reuse those tokens and read as native run.human / AdminConsole. Introducing shadcn or any new design system is out of scope and explicitly forbidden by the phase constraints. shadcn gate → resolved to "existing HeroUI"; no third-party registry.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (existing run.human HeroUI system — no shadcn init) |
| Preset | not applicable |
| Component library | HeroUI (`@heroui/react ^2.8.8`) + hand-rolled `cls.*` primitives in `src/components/admin/qr-ui.ts` |
| Icon library | `lucide-react ^0.561.0` (primary) with `react-icons ^5.5.0` available; QR admin today is largely icon-light — use lucide sparingly for affordances (copy, chevron, external-link) |
| Font | Headings `font-museo` (site display face); body/UI = inherited site sans (Tailwind default stack) |
| QR rendering | `qrcode ^1.5.4` (already a dependency) — client-side `toDataURL` / `toCanvas`. NO new runtime dependency. |
| Region base for client fetches | `apiBase()` from `qr-ui.ts` (`/use1` prefix in prod) |

**Source-of-truth reuse rule:** every surface in this phase composes from `cls.*` (`cardPad`, `card`, `label`, `input`, `select`, `textarea`, `btn`, `btnPrimary`, `btnDanger`, `h1`, `h2`, `sub`, `mono`). Do NOT hand-author new one-off Tailwind color/spacing values where a `cls.*` token exists. New tokens (e.g. a segmented-control class, a chip class, a reward-card class) are added to `qr-ui.ts` so both surfaces and future slices (55/56) inherit them.

## Spacing Scale

Base unit 4px (Tailwind). The `/admin/qr` surface established a small set of half-steps for dense admin forms; this phase stays consistent with them rather than re-spacing the surface.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`gap-1`, `mb-1`) | icon gaps, tight label offsets |
| sm | 8px (`gap-2`, `p-2`) | compact control spacing, chip padding |
| md | 16px (`gap-4`, `p-4`) | default: card padding (`cls.cardPad`), section gaps in the form column |
| lg | 20px (`gap-5`, `py-5`) | root form column gap (`cls.root` = `gap-5`) |
| xl | 32px (`gap-8`) | major section breaks between form sections (Name / Answer type / Scoring / Unlock / Advanced) |

**Exceptions (inherited from `qr-ui.ts`, keep for surface consistency — do NOT "correct" to pure 4-multiples):**
- `gap-2.5` = 10px — inner grids of scoring inputs.
- `px-3.5` / `py-2.5` = 14px / 10px — button and error-banner padding.
- `text-[12.5px]` help text (see Typography).
- Control height `h-9` = 36px for all inputs/selects/buttons (fixed line-height rhythm). Touch targets that are icon-only must be ≥ 40px hit area (pad the button, keep the 36px visual).

## Typography

Established `/admin/qr` type ramp (from `cls.*`). Declared roles:

| Role | Size | Weight | Line Height | Token |
|------|------|--------|-------------|-------|
| Display (page H1) | 24px (`text-2xl`) | 700 bold | 1.2 tight | `cls.h1` (`font-museo tracking-tight`) |
| Heading (section H2) | 18px (`text-lg`) | 600 semibold | 1.25 | `cls.h2` (`font-museo`) |
| Label / eyebrow | 11px uppercase, `tracking-wide` | 600 (rendered bold via caps) | 1.4 | `cls.label` (`text-default-400`) |
| Body / input | 13px (`text-[13px]`) | 400 | 1.5 | `cls.input`, control text |
| Help / caption | 12.5px (`text-[12.5px]`) | 400 | 1.5 | `text-default-500` help copy under fields |
| Body (reward card) | 14px (`text-sm`) | 400 | 1.5 | reward-card descriptive copy |
| Mono (codes / otpauth / challenge) | 13px | 400 (500 for emphasis) | 1.4 | `cls.mono` / `font-mono` — rolling codes, `otpauth://`, challenge slug |

**Weight rule:** primary pair is **regular 400 + semibold 600**. `700 bold` is reserved **only** for the page H1 (`cls.h1`) — an existing site convention; do not introduce a third weight elsewhere.

**Rolling-code emphasis:** the *current* OTP code renders larger and mono to read as the hero value of the reward card — 28px (`text-[28px]`) mono, weight 600, `tracking-wide`; previous/next codes render at 13px mono `text-default-400`.

## Color

Uses HeroUI semantic tokens (theme-driven, light+dark safe) — never raw hex in components except the fixed DC34 celebration palette. The `10%` accent is HeroUI `primary` (the DC34 mint/teal), already used by `cls.btnPrimary` (`bg-primary text-black`).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` / page surface | page + form column background |
| Secondary (30%) | `bg-content1` (cards), `bg-content2` (hover / table head / drawer body) | every `cls.cardPad` section card, Advanced drawer body, reward card body |
| Border / structure | `border-divider` | all card, input, chip, tier-row borders |
| Accent (10%) | `primary` (DC34 mint/teal) | see reserved-for list |
| Destructive | `danger` | Delete button, error banner (`border-danger text-danger bg-danger/10`), destructive confirms |
| Muted text | `text-default-400` (labels), `text-default-500` (help) | de-emphasized copy |
| Success / solved | `success` | reward-card "Solved" header accent, "code accepted" affirmations only |

**Accent (`primary`) reserved for — explicit list (never "all interactive elements"):**
1. Primary CTA buttons only — `Create challenge` / `Save changes` (`cls.btnPrimary`).
2. Focus ring on inputs/selects (`focus:border-primary`, existing).
3. The **selected** segment of the challenge-type preset control and the Answer-type (Static / Rotating OTP) segmented control.
4. The active/selected challenge-type preset chip and the Static "Reward → OTP enrollment" enabled-state indicator.
5. The live scoring-preview headline number (the computed points value).
6. Reward card: the "Add to Authenticator" primary action + the QR frame accent.

Secondary buttons stay neutral (`cls.btn`, `border-divider` on `bg-content1`). Destructive stays `danger`. The DC34 confetti palette (`#00d4aa #ff2fb9 #ff5c72 #5eead4 #ffd700`) is owned solely by `CtfCelebration.tsx` and is **not** reused in this phase's chrome.

## Component Inventory

### Surface A — `CtfForm.tsx` redesign (design "A"), admin-facing

Restructured into ordered sections, each a `cls.cardPad` card in a `cls.root` (`gap-5`) column. `mode: "create" | "edit"`; edit-mode infers challenge-type + answer-type from the loaded record.

| # | Section | Controls | Notes |
|---|---------|----------|-------|
| 1 | **Name** | `Challenge name` text input (immutable in edit, `opacity-60` disabled) | keep existing lowercase + resolver-URL help line |
| 2 | **Challenge type** | Segmented / chip control: Flat points · First-blood race · Timed drop · Easter egg · Custom | selecting a preset pre-fills the Advanced drawer scoring knobs; selection state = `primary` accent; does NOT lock Advanced |
| 3 | **Answer type** | Segmented control: Static · Rotating OTP | drives which sub-controls render (below); inferred in edit mode |
| 3a | Static sub-panel | masked `Answer` input (write-only, never prefilled) + **Reward → OTP enrollment** toggle → when on: `otpauth://` secret input (masked/write-only) + `Reveal preview` showing the reward card | reuse existing masked-answer pattern + placeholder `•••••• (leave blank to keep)` |
| 3b | Rotating OTP sub-panel | `otpauth://` secret input (masked/write-only) + read-only summary of parsed digits/period/algorithm once entered | secret never round-tripped on edit; show `•••••• (set — leave blank to keep)` |
| 4 | **Scoring window & limits** | `Interval (hours)` (per-24h), `Per-player max`, `Global max` numeric inputs + the Slice-2 placeholder note | all round-trip through save/edit; help copy per Copywriting |
| 5 | **Unlock & chaining** | `Hidden until flag` text input | free-text challenge name; chain-break warning copy |
| 6 | **Advanced** (drawer, always editable) | collapsible; raw knobs: Point max, Point floor, Max solves, First-blood bonus, Time tiers (existing tier editor), Max attempts, Rate-limit window (s), Enabled checkbox, raw Effect JSON textarea | presets pre-fill; a preset never disables these; drawer defaults collapsed in create, collapsed in edit unless a non-preset-derivable value is present |
| 7 | **Live scoring preview** | read-only computed panel mirroring `computePoints` | recomputes on any scoring-relevant change; hero number in `primary` |
| — | **Actions** | `Create challenge`/`Save changes` (primary), `Cancel`, `Delete` (edit only, right-aligned danger) | unchanged layout from current form |
| — | **REMOVED** | the standalone `Points` field | deleted per design decision — replaced by the Ceiling / curve model |

**Advanced drawer pattern:** use a lightweight disclosure (button header with chevron toggling body visibility) built from `cls.*`, or HeroUI `Accordion` if it themes cleanly against `bg-content2` — prefer the hand-rolled disclosure to match the flat admin aesthetic and avoid HeroUI card-shadow drift. Body sits on `bg-content2` inside a `cls.card`.

**Segmented control (new `cls` token):** add `cls.segment` / `cls.segmentActive` to `qr-ui.ts` — a row of `h-9` buttons, `border-divider`, selected = `bg-primary text-black`, unselected = `bg-content1 text-foreground hover:bg-content2`. Reused by both the challenge-type and answer-type selectors.

### Surface B — `otp-enroll` reward renderer (new component), player-facing

New client component (e.g. `CtfOtpEnroll.tsx`) dispatched when a **non-covert** solve response carries `effect.kind === "otp-enroll"`. This is the first `effect.kind` dispatch on the client; wire a small `effect`-switch at the non-covert solve success site (NOT `EggTrigger`/`covert-egg` — those stay byte-identical and carry no reward).

| Element | Spec |
|---------|------|
| Container | `cls.card` on `bg-content1`, `p-4`, max-width ~ `380px`, centered; success accent on the heading |
| QR | client-rendered from `effect.otpauth` via `qrcode.toDataURL`/`toCanvas`; ~200–240px square; white quiet-zone background (QR must remain high-contrast regardless of theme — render on white, not `bg-content1`); `alt`/`aria-label` = "Authenticator enrollment QR code" |
| Rolling code | `adjacentCodes(secret, now, opts)` → Previous / **Current** / Next; current = 28px mono hero (`primary`); previous/next = 13px mono `text-default-400`; live countdown `New code in {n}s` from `remainingSeconds`, ticking every 1s |
| Add to Authenticator | primary action (`cls.btnPrimary`) → `href = effect.otpauth` (`otpauth://` deep link) |
| Copy setup link | secondary (`cls.btn`) → copies `effect.otpauth`, toast `Copied` |
| Next flag | conditional line `This unlocks: {nextFlag}` when `effect.nextFlag` present |
| Countdown timer | single `setInterval(1000)`, cleared on unmount; recompute `adjacentCodes` when the period rolls (remainingSeconds hits 0) |
| Parsing | reuse Phase-53 `parseOtpauth` / `adjacentCodes` from `src/lib/ctf-otp.ts`; do not re-implement |

## Interaction & State Contract

| Concern | Contract |
|---------|----------|
| Preset → Advanced | Selecting a challenge-type preset writes concrete values into the Advanced knobs (curve/tier/anti-spam) via a pure `presetToAdvanced(preset)` map; the knobs remain user-editable afterward (SC-1). |
| Live preview parity | The preview computes points by calling a **shared pure helper extracted from `computePoints`** (not a re-implementation) so preview === judge for identical inputs (SC-3). Extract the helper in `ctf-judge.ts` (or a sibling pure module) and import into the form. |
| Secret / answer masking | On edit, answer + OTP secret + reward-otpauth fields are **empty**, placeholder-masked, and never populated from the loaded record (server never sends plaintext); blank-on-save = keep existing (SC-2). |
| Round-trip | `Interval (hours)`, `Per-player max`, `Global max`, `Hidden until flag` all persist and re-hydrate on edit (values, not secrets) (SC-3). |
| Edit-mode inference | Answer type inferred from the loaded record (`answerType`, default `static`); challenge-type inferred from the scoring shape, defaulting to `Custom` when no preset matches. |
| Covert invariant | `covert-egg.ts`, `EggTrigger.tsx`, `CtfCelebration.tsx` are untouched; the reward dispatch lives only on the non-covert solve path (SC-5). No reward payload on the covert channel. |
| Reward malformed | Missing/unparseable `otpauth` → renderer no-ops silently; the base solve success still shows. |
| Loading/busy | Form disables all actions while `busy`; reward card QR shows nothing until `toDataURL` resolves (fast; no spinner needed, but guard against flash by rendering the code+countdown first). |

## Accessibility

- All inputs keep a visible `cls.label`; segmented controls are keyboard-operable (`role="radiogroup"` / `role="radio"` or native radios styled as segments) with visible focus (`focus:border-primary` / focus ring).
- QR carries an `aria-label`; the manual `Add to Authenticator` + `Copy setup link` give a non-scan path (screen-reader / desktop users).
- Countdown uses `aria-live="polite"` sparingly (announce on period roll, not every second — throttle or mark the seconds span `aria-hidden` and announce only "New code available").
- Contrast: QR always on a white quiet zone; body text uses HeroUI default/foreground tokens that pass AA in both themes.

## Decisions Log (autonomous — recorded, not asked)

- **D1 — Design system:** keep existing run.human HeroUI + `qr-ui.ts` tokens; shadcn not initialized (would violate "do not invent a new design system"). `Tool: none`.
- **D2 — New shared tokens** (`cls.segment*`, chip, reward-card) are added to `qr-ui.ts` so surfaces + future slices inherit them, rather than one-off Tailwind in components.
- **D3 — Advanced drawer** is a hand-rolled disclosure on `bg-content2`, preferred over HeroUI `Accordion`, to match the flat admin aesthetic.
- **D4 — Rolling-code hero** current code at 28px mono `primary`; a documented type addition scoped to the reward card (not a global ramp change).
- **D5 — Slice-2 scoring window** rendered as an informational placeholder note only (no interactive day/time/tz picker) — that ships in Phase 55.
- **D6 — Live preview** binds to a pure helper extracted from `computePoints`, not a duplicate, to guarantee parity.
- **D7 — Reward dispatch** wired at the non-covert solve success site with a small `effect.kind` switch; covert path untouched and byte-identical.
